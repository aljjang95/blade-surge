# UI·UX 전면 점검 (2026-10-28)

대표님 요청(2026-10-27): 인터페이스를 전부 열어 보고, 한눈에 보이지 않는 화면을 정리한다. '자세히 보기'를 눌러야만 알 수 있는 필수 정보와 지나치게 큰 버튼 때문에 핵심 정보가 밀려나는 화면을 고친다.

## 측정 방법

- 로컬 빌드(`bun run build` → `vite preview`)를 Playwright Chromium(SwiftShader)으로 열고 실제 클릭으로 순회했다. 기준 화면 844×390(가로 폰), 보조 640×360·1280×720.
- 세이브: 빈 저장(신규 흐름: 부팅 → 시작 영웅 선택 → 로비 → 1-1 → 결과), `test/fixtures/saves/late.json`(로비 메뉴 23개 항목 전부, 영웅·장비 4탭).
- 화면마다 보이는 상호작용 요소의 크기·뷰포트 대비 면적·중심 적중·잘림, 11px 미만 글자, 내용이 넘치는 스크롤 영역(보이는 높이/내용 높이)을 쟀다. 스크립트는 `work/uiux/`(커밋 안 함).
- 이것은 브라우저 뷰포트 측정이다. 실기기 터치·GPU 판단이 아니다.

## 판정 기준

- 한눈에: 그 화면의 목적 정보(목록·수치·주요 행동)가 첫 화면(스크롤 0)에 보이는가. 844×390에서 본문이 화면 높이의 50% 미만이면 P1.
- 숨은 필수 정보: 결정을 내리는 데 필요한 값(보상·비용·효과·진행도)이 '안내·자세히'를 눌러야만 보이면 P1, 부가 설명이면 P3.
- 버튼 비율: 터치 최소 44px는 지킨다. 보조 버튼이 주요 행동보다 크거나, 한 버튼이 화면 면적 4%를 넘으면 지적(주 행동 '출격'·'공격' 제외).
- 겹침·잘림: 상호작용 요소끼리 2px 넘는 겹침, 조상 overflow 잘림, 뷰포트 밖 = 결함.
- 전투 중 플레이 영역 위 팝업 금지(전역 규칙).

## 공통 규칙 (이번에 정한 것)

`src/ui/density.css`가 짧은 가로 화면(높이 ≤ 500px)의 공통 크기 단계를 정한다.

- 터치 최소 44px는 그대로. 보조 버튼은 44px, 주 행동은 최대 52px. 화면 폭 전체 버튼은 쓰지 않는다(바닥 행동 줄 제외).
- 탭 줄은 한 단 44px. 하위 탭은 같은 줄의 칩으로.
- 장식 배너는 짧은 가로에서 한 줄 머리(≤ 56px)로 줄이고 그림은 작은 아이콘으로.
- 결정에 필요한 값은 접지 않는다. '안내'에는 부가 설명만 둔다.
- 본문 글자 최소 11px.
