# Blade Surge 실제 플레이 QA — 입력 포커스·회피 스킬·로비 카메라 (2026-09-27)

기준: main 73cd2fc0f647828336a7cba87a75681d08c85dbe, 로컬 Vite 127.0.0.1:5187, Chrome 1280×720 헤드 모드.

같은 자동 플레이 드라이버를 두 방식으로 돌렸다. 기준선은 미리 정한 버튼 계획으로, 비교군은 매 화면에서 보이는 버튼 후보를 Jev에 보내 다음 버튼을 고르게 했다. 결함 재현 절차는 두 방식 모두 동일한 키 입력 순서다.

## 수정 전 재현 (4회 실행 × 각 2회 시도, 8/8 재현)

| ID | 재현 | 수정 전 결과 |
|---|---|---|
| S3 AUTO 포커스 | 전투 중 AUTO를 마우스로 켜고 끈 뒤 J, Space | 포커스가 AUTO에 남아 J 공격 무시. Space가 AUTO를 다시 눌러 자동 전투 설정까지 저장 |
| S1 회피 중 스킬 | K 입력 약 0.14초 뒤 1 입력 | 스킬 입력이 소비만 되고 사라짐. MP 변화 없음. 회피 종료 후 입력(대조군)은 정상 발동 |
| S2 로비 복귀 카메라 | 결과 화면 → 로비 | 첫 프레임 카메라가 최종 위치에서 80~98 떨어진 전투 카메라 위치. 약 1.9초 동안 성 외곽 지형이 보인 뒤 영웅 구도로 도착 |
| S4 새로고침 저장 | 로비 → 새로고침 → 재부팅 | 결함 없음. 골드·보석·진행·튜토리얼 완료 상태 동일 |

## 수정

- HUD 버튼(AUTO·일시정지·보스 직행)을 마우스·터치로 누른 뒤 포커스를 해제한다. 키보드로 누른 경우는 유지한다.
- 회피 중 누른 스킬은 마지막 입력 하나만 예약해 회피가 끝나는 프레임에 발동한다. 새 회피와 부활 때 예약을 지운다.
- 전투에서 로비로 돌아오는 첫 프레임은 로비 카메라 위치로 바로 둔다.

## 수정 후 확인

- 실제 플레이 2회(각 2회 시도): J 공격 정상, Space가 AUTO를 바꾸지 않음, 회피 중 입력 스킬이 회피 직후 발동(MP 감소 확인), 로비 첫 프레임부터 최종 구도(최대 이탈 0).
- bun run check: 964 pass, 1 기존 skip, 0 fail, build 통과. 새 회귀 테스트 5개는 수정 전 코드에서 3개 실패.
- 독립 코드 검토에서 같은 프레임 다중 스킬 입력 순서 문제를 지적받아 입력 큐 순서를 따르도록 보완하고 테스트를 추가했다.

## 미검증

실기기 터치, 파티 모드(원격 입력 350ms 만료 경계), 오디오, 성능 수치는 이번 범위에서 확인하지 않았다.
