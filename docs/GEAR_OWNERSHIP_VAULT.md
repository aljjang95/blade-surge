# 장비 영웅 귀속 · 금고 계약

2026-10-28 RPG 핵심 레인(`claude/gear-vault`). 대표님 요청(원문): "캐릭터들 보유하고 있을 때 무기들이 공유가 되는 기준이던데, 각자마다 그 캐릭터로 진행했을 때 뜨는 무기로 진행해 주고, 실제 드랍할 때 금고를 통해 옮기는 기준으로 됐으면 좋겠다. 이 부분의 넘나듦도 컨텐츠화할 수 있는 영역인데 말이지."

정본 코드: `src/game/gear-vault.js`(순수 규칙·수치·이관) · `src/game/economy.js`(명령) · `src/game/save-base.js`(로드 이관) · `src/shared/settlement.js`(서버 정산 귀속) · `src/shared/v1-ops.js`(서버 명령) · `src/ui/vault-panel.js`(금고 화면).

## 1. 이전 구조

- `s.inventory` 하나를 모든 영웅이 공유했다. `hero.equip[slot] = uid`로 아무 영웅이나 장착했고, 다른 영웅이 끼고 있던 장비는 "옮겨 장착"으로 공짜로 빼앗아 왔다.
- 드랍은 `addItem`(필드·완료 상자·가챠 SSR 장비), `rollResult`(장비 소환), `craftSetItem`(제작), `town-service`(마을 상점·제작), 서버 `grantLootItem`(서버 권위 정산)이 인벤토리에 넣었고 누구 것이라는 정보가 없었다.
- `inventory`·`invSeq`는 `PARITY_KEYS`/`SERVER_OWNED_KEYS`에 들어 있다(서버 권위 계정에서는 서버 문서가 덮는다). 그래서 귀속 규칙은 클라이언트와 서버가 함께 실행하는 `Economy` 안에 둔다(서버 `/cmd`는 같은 메서드를 부른다, `worker/v1/state.ts`).

## 2. 새 규칙 (1단계, 이번 브랜치)

### 2.1 귀속
- 장비 인스턴스마다 `owner`가 있다: 영웅 id(`HEROES`의 키) 또는 `'vault'`.
- **얻은 영웅이 주인이다.** 전투·정산 드랍(필드 드랍, 완료 상자, 서버 정산 `grantLootItem`)은 그 판을 뛴 영웅(전투 장부 `_fieldRewards.heroId`, 서버는 티켓의 `hero_id`) 소유다. 소환·제작·상점·우편처럼 전투가 아닌 획득은 **지금 고른 영웅**(`s.selected`) 소유다.
- 영웅 화면 가방·장비 인벤토리 창·성장 추천·전리품 비교는 **그 영웅 소유 장비만** 보여 준다.
- `equip(heroId, uid)`는 `owner === heroId`일 때만 된다. 다른 영웅 소유 장비는 장착할 수 없고, "다른 영웅에게서 옮겨 장착"은 없어졌다(유일한 이동 통로는 금고). 서버 `/cmd equip`도 같은 메서드라 같이 거부된다(422 rejected).
- 장착 = 소유다(정규화는 `equip`을 정본으로 보고 `owner`를 그 영웅으로 맞춘다). 강화·룬·판매·분해는 주인과 상관없이 uid로 한다(강화 상태·룬 소켓·고통 단계 `tp`는 그대로).

### 2.2 금고(창고) — 넘나듦 콘텐츠
| 규칙 | 값 | 이유 |
|---|---|---|
| 맡기기(영웅 → 금고) | 무료. 장착 중이면 먼저 해제 | 정리 행동에 비용을 매기면 금고를 안 쓴다. 비용은 "다른 영웅이 가져갈 때" 한 번만 |
| 꺼내기(금고 → 영웅) | 골드 = 등급 기본값 × (1 + 강화/10), 10 단위 올림. 기본값 N 500 · S 2,000 · E 8,000 · U 25,000 · L 80,000 | 강화·등급에 비례한 비용이 "좋은 장비를 키운 영웅에게 둘지, 옮길지"의 선택을 만든다. `sim:90d` 하루 골드 수입(W1 약 170만, W5 이후 약 1,000만) 대비 L+20이 24만: 초반엔 큰 결정, 후반엔 하루 5회 상한이 실제 제약. 후반 비중이 작다는 점은 조정 손잡이(`VAULT.withdrawBase`)로 남긴다 |
| 무료 꺼내기 | ① 맡긴 영웅에게 되돌리기 ② 맡긴 영웅과 같은 무기 계열(`kitOf`: 레인저↔검은고양이, 바바리안↔늑대인간) ③ 공유 시절 장비(`legacy`)의 첫 이동 | 보관만 하던 사람을 벌주지 않는다. 같은 계열은 무기 모양이 같아 "같은 길의 계승"으로 읽힌다. 기존 저장은 원래 공짜로 옮길 수 있었으므로 한 번은 공짜로 지켜 준다 |
| 하루 유료 꺼내기 | 5회(05:00 KST 기준 `periodAt` 날짜, 날짜는 앞으로만) | 주력 장비를 매 판 돌려 쓰는 "공유 체제"로 되돌아가지 않게 하는 상한. 무료 꺼내기는 세지 않는다 |
| 강화 손실 | 없음. 강화·룬·고통 단계 그대로 이동 | 손실은 체감이 나쁘고 파괴 확률과 겹쳐 분노 요소가 된다. 대신 비용이 강화에 비례한다 |
| 칸 수 | 기본 20칸, 확장 1회 +10칸, 최대 8회(100칸) | 금고는 무한 창고가 아니라 "계승할 장비를 고르는 곳" |
| 확장 비용 | 골드 50,000 × 2^n(n = 이미 한 확장 수): 5만 → 640만, 합계 1,275만 | 장기 골드 싱크(W5 이후 하루 수입 1.3일분, 초반엔 수 주). 유료 재화 없음 |

- 금고 안 장비에는 `from`(맡긴 영웅 id)이 붙는다. 꺼내면 `from`과 `legacy`가 지워진다.
- 금고 상태: `s.vault = { v: 1, expansions, day, used }`. `inventory`(장비별 `owner`·`from`·`legacy`)와 함께 서버 소유 키다(`PARITY_KEYS`에 `vault` 추가).

### 2.3 버린 안
- **강화 단계 손실(-1~-3) 이전**: 손실이 파괴·하락과 겹쳐 키운 장비를 옮기는 행동 자체를 막는다. 비용 비례로 대체.
- **이전석(새 재화)**: 상점·가격은 BM 레인(session_01H8mx3SKmnsC35B9NZCgXoQ) 소유다. 1단계는 골드만 쓰고, 이전석·확장권은 아래 3절 계약으로 넘긴다.
- **미장착 장비 전부 금고로 이관**: 기존 저장의 가방이 갑자기 비고 금고 칸(20)을 넘친다. 지금 고른 영웅에게 두는 쪽이 화면이 그대로다.
- **소환·제작 장비는 금고로**: 금고 칸이 가득 차면 얻을 곳이 없어진다. 지금 고른 영웅에게 준다.
- **계열 단위 공유(같은 계열은 금고 없이 공유)**: 같은 계열 영웅이 둘뿐이라 규칙만 늘어난다. 금고 무료 꺼내기로 같은 효과.

## 3. 다음 단계(문서만, 이번 범위 밖)
- 이전석(`transferStones`): 유료 꺼내기 1회를 골드 대신 이전석 1개로. 획득처 = 무한의 성 주간 보급·시즌 이벤트(무료), 상점 패키지는 BM 레인 결정. 확장권(`vaultTicket`): 확장 1회를 골드 대신. 두 재화 모두 `addRewards`·`IAP_REWARD_KEYS`에 넣는 일은 BM 레인 승인 뒤. BM 세션에 계약을 한 번 알렸다.
- 금고 전용 콘텐츠: "계승 의식"(같은 계열 영웅에게 L 장비를 넘기면 칭호·아바타 조각), 금고 진열(보관 중 세트 수집 도감 보너스), 주간 "유랑 상인의 맡김"(금고 장비 하나를 하루 빌려 주면 보상).
- 금고에서 바로 판매·분해(지금은 영웅에게 꺼내거나 맡긴 영웅 가방에서 하는 대신 금고 시트에서 강화만 불가). 1단계는 꺼내기·맡기기만.

## 4. 기존 저장 이관 (사용자 데이터 이관 = 고위험)
- 위치: `save-base.js normalizeSave` → `normalizeGearOwnership(s, raw)`. 클라이언트 `Economy.migrate`(로컬 로드·서버 문서 적용 `account.js`)와 서버 `EconomyCore.fromState`(모든 `/cmd`·`/runs`·`/me`)가 같은 함수를 지난다.
- 규칙:
  1. 장착 중 장비 → 그 영웅 소유(장착 정규화 뒤라 한 장비는 한 영웅에게만 장착되어 있다).
  2. 원본에 `vault`가 없는 저장(귀속 이전 저장)의 미장착 장비 → 지금 고른 영웅(`selected`, 소유 정책 정리 뒤 값) 소유 + `legacy: 1`(첫 이동 무료).
  3. 원본에 `vault`가 있는데 `owner`가 없거나 모르는 값인 장비 → 지금 고른 영웅(`legacy` 없음). 정상 경로에서는 생기지 않는 방어 규칙이다.
  4. `owner === 'vault'`인데 `from`이 모르는 값이면 `from`을 지운다(유료 꺼내기).
- 멱등: 두 번째 로드에서는 `raw.vault`가 있고 모든 장비에 `owner`가 있으므로 바뀌는 것이 없다(테스트 `gear-vault.test.ts`: 이관 결과를 다시 이관해도 같은 JSON).
- 보존: 장비 수·uid·id·강화·`tp`·룬 소켓(`restoreSockets`)·`invSeq` 그대로. 삭제 없음.
- 롤백: 필드는 추가만 한다. 이전 클라이언트·이전 서버 배포는 `normalizeSave`가 `{ uid, id, enh, tp }`만 다시 만들고 `vault`를 모르는 키로 버리므로 공유 체제로 그대로 읽는다(장비 손실 없음, 금고 확장에 쓴 골드만 돌아오지 않음). 다시 새 버전으로 오면 2번 규칙으로 다시 이관된다.
- 가져오기(`legacy-sanitize.js`): 조작 저장이 금고 확장·`legacy`를 주입해도 얻는 것은 골드 비용뿐이다. 확장 수는 0~8로 자르고, 하루 사용량은 서버 시계로 다시 계산된다. 별도 정화는 하지 않는다.

## 5. 서버 정합
- 새 `/cmd` 명령(`src/shared/v1-ops.js`): `vaultDeposit [uid]`, `vaultWithdraw [uid, heroId]`, `vaultExpand []`. 같은 이름의 `Economy` 메서드를 부르므로 클라이언트 명령 큐(`src/net/command-queue.js`)가 자동으로 감싸 서버로 보낸다. 서버는 서버 시계로 하루 횟수를 센다.
- 서버 정산: `applySettlement`가 `grantLootItem(eco, item, tp, heroId)`로 티켓 영웅에게 귀속한다. 완료 상자(`completeStage`)도 장부 영웅에게 준다.
- `equip`은 서버에서도 `owner` 검사를 거친다. 다른 영웅 장비 장착은 422.
- `PARITY_KEYS`에 `vault`를 넣었다. 배포 전후 해시 값은 달라지지만 다음 `/me`·`/cmd` 응답의 `stateHash`로 다시 맞는다(기존 `roster` 추가와 같은 방식, 정보용 비교).
- 결제 플래그·`V1_ENABLED` 기본값은 바꾸지 않았다.

## 6. UI
- 영웅 화면 가방(`gear-panel.js renderBag`): 그 영웅 소유 장비만, 막대에 `금고 n/칸` 버튼.
- 장비 시트: 하단에 `금고에 맡기기`(장착 중이면 해제 후 맡김). "다른 영웅에게서 옮겨 장착" 문구는 없어졌다.
- 금고 화면(`vault-panel.js`, `vault.css`): 칸 수·확장 버튼(비용), 오늘 남은 유료 꺼내기, 장비 타일(맡긴 영웅·무료/비용 표시), 선택 시 `이 영웅에게 꺼내기 · 골드 N`/`무료`. 비용이 부족하거나 하루 횟수를 다 쓰면 버튼이 막히고 이유를 보여 준다.
- `density-*.css`(UI 레인)와 상점 UI(BM)는 건드리지 않았다.

## 7. 90일 시뮬레이션 영향
- `tools/sim-90d.mjs`는 페르소나마다 영웅 하나(기사)의 드랍·장비만 모델링한다. 한 영웅으로 진행하면 모든 드랍이 그 영웅 소유라 귀속 전후 곡선이 같다. 결과는 8절에 기록.
- 다중 영웅 플레이(부캐)는 새 영웅이 자기 드랍으로 시작하고, 주력 장비를 금고로 옮기려면 골드를 낸다. 이것은 의도한 속도 저하(부캐 육성 = 콘텐츠)이며 시뮬레이터 밖이다. 다음 단계에서 부캐 페르소나를 추가할 때 이전 비용을 골드 소모처로 넣는다.
