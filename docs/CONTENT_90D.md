## 1. 왜 필요한가 — 현행 진행 곡선

`tools/progression-estimate.mjs` 실측: 하루 30분이면 스토리 캠페인 6지역 60관문이 **7일**에 끝난다(Lv.44). 그 뒤 성장 목표는 숙련·악몽 난이도, 원정 던전, 일일 계약뿐이었고 "다음 단계"가 없는 구간이 생긴다. 새 지역(7~12장)은 보스·맵·모델·음악 레인이 필요한 큰 제작물이라, 이번 덩어리는 **기존 자산을 다시 쓰는 진행 층**(지옥 난이도·무한의 성·주간 루프·시즌 이벤트)으로 90일을 채우고, 시뮬레이터로 그 길이를 증명한다.

## 3. 들어간 콘텐츠

### 3.1 지옥(HELL) 난이도
- 해금: 지역 10관문을 모두 **악몽 이상**으로 클리어하면 그 지역의 지옥이 열린다(`endgame.peak`에 관문별 최고 난이도 기록, `recordDifficultyClear`).
- 배율: 적 체력 ×2.8 · 공격 ×2.1 · 밀도 ×1.25 · 보상 ×2.4 · EXP ×2.2. `DIFFICULTY_ORDER`에 들어가 `loot-tables.js`가 지옥 행(상위 강화석·초월석·L 가중)을 자동 생성한다(드랍 보고서 54→72행).
- 서버 정산(`shared/settlement.js`)과 같은 `applyDifficulty`/`resolveDifficulty`를 쓰므로 서버 권위 캠페인 런에도 그대로 적용된다.

### 3.2 무한의 성
- 개방: 2-10 첫 클리어(진행도 21). 에너지 없음, 도전은 **다음 층 하나**(`recordTowerClear`: best+1·상한 이하·영수증 1회).
- 층 구성: 10층이 한 지역(1~10층 = 1지역 … 61층부터 다시 1지역), 5층 중간 보스·10층 지역 최종 보스. 맵·몬스터·보스·이야기 자산은 원본 관문 그대로(새 자산 없음, 무료 킷 없음).
- 적 배율 = 8.9 × 층^0.55 (1층 ≈ 2-8, 100층 ≈ 6-10의 4.6배). 거듭제곱 곡선이라 후반 성장 속도에 맞춰 하루 1층 안팎으로 오른다.
- 시즌 상한: 30층 + 주당 15층(W12 = 210층, 최대 300). 최고 기록 아래로는 줄지 않는다.
- 첫 돌파 보상: 골드 300×1.02^(층-1)(100층 2.1천 · 210층 1.9만 · 300층 11.2만, 미드 일수입 68만 대비 작게) · 강화석 2, 5층마다 상급 강화석, 10층마다 전설 강화석·보석 50, 25층마다 초월석.
- 주간 보급: 이번 주에 한 층 이상 돌파했으면 최고층 구간(1/20/40/70/100/150층) 상자를 주 1회. 주차는 앞으로만 간다(기기 시계를 되돌려도 지난 주로 돌아가 다시 받을 수 없음, 시즌 전은 별도 주차 1). 계정 서버에 연결되면 상한·보급·이벤트가 서버 시각(`AccountClient.serverNow`)을 써서 기기 시계 앞당김도 막는다. 오프라인 로컬은 기기 시계를 쓴다(기존 일일 의뢰와 같은 한계).
- 탑 임무 면제: 이번 주 상한에 닿으면 `daily_tower`·`weekly_tower`는 채울 방법이 없으므로 달성으로 처리한다(`contractRows/claimContract`의 `waived`).
- 결과 화면: "N+1층 도전"(패배 시 "N층 다시"), 2배·다음 관문 버튼 없음. 정산 거절(중복·순서·상한)은 보상 없이 닫힌다.

## 4. 진행 시뮬레이션 (D8 증명)

`bun tools/sim-90d.mjs --assert` (시드 16, 결정적). **시뮬레이터는 실제 `Economy`·전투를 돌리지 않는 근사 모델이다**: 데이터 모듈과 순수 함수(perRun·heroStats·itemStats·강화 규칙·endgame-core)를 같은 값으로 읽어 하루 단위로 쌓을 뿐이며, 승패는 아래 요구 전투력 식으로 판정한다. 모델: 실제 `perRun`(Floor 방 구성·loot-tables)·`heroStats`·`itemStats`·강화 확률·하락·파괴·훈련 골드, 장비 드랍과 강화만 시드 난수. 요구 전투력 = 2700 × 적배율^0.6 × 난이도 압박(√(체력×공격)·√밀도) — 현행 7일 캠페인 실측으로 보정. 재료 던전·소환·결제·광고 보상은 빼서 **보수적**이다.

페르소나: 라이트 15분×1세션(손기술 1.1), **미드(일반) 30분×2세션**(1.0), 하드코어 100분×3세션(0.88). 무과금 초월(SSSR)일은 `ECONOMY_PACE`를 플레이 분량으로 환산(라이트 97 · 미드 64 · 하드코어 31일).

## 5. 서버 권위(v1 원장)와의 경계
- 캠페인(지옥 포함)·이벤트 보상: `completeStage` 안에서 계산 → 서버 `/runs/settle`의 `settlement.js`가 같은 함수를 서버 시계로 부르므로 클라이언트와 서버 결과가 같다.
- 무한의 성: 아직 서버 런 종류(`kind:'tower'`)가 없다. `net/account.js`가 서버 권위 런 대상에서 제외하고, `app.startTower`/`startStage`는 `authority==='server'`에서 진입을 막는다(그림자 모드는 정산 뒤 스냅샷). P2에서 `runs/start {kind:'tower', contentId:'T<층>'}` + `recordTowerClear` 순수 함수를 서버 규칙 엔진에 그대로 올리면 된다(영수증 id·순서·상한 검사가 이미 순수 함수).
- 주간 보급·임무 수령: v1 `OPS`에 `claimTowerChest` 추가가 필요(서버 시계). 이번 덩어리에서는 로컬 경로만.

### 5.1 리뷰 반영(지휘 세션 독립 리뷰, P1 1 · P2 7)
- P1 시계 되돌림으로 주간 보급 반복 수령 → 주차 단조 증가·`chestWeek >= week`, 되돌림 테스트 추가.
- P2 시계 앞당김 → 계정 연결 시 서버 시각 사용(`eco.trustedClock`). 오프라인 로컬은 남은 한계.
- P2 시즌 전 주차 id 충돌 → 시즌 전 1, 시즌 n주차 n+1(0 = 기록 없음).
- P2 서버 모드 → 탑 진입·주간 보급·지옥 출격을 서버 권위 계정에서 막고, 그림자 모드는 탑 정산·보급 뒤 스냅샷. `endgame`은 `journey`·`expedition`처럼 아직 서버 명령이 없는 로컬 필드라 `PARITY_KEYS`/`SERVER_OWNED_KEYS`에 넣지 않는다(넣으면 서버 문서가 비어 있는 동안 기록을 지운다).
- P2 기존 저장 이월 → `migrateEndgame`: 별점 관문은 스토리, 숙련 기록(최근 20판)의 캠페인 승리는 그 난이도. 옛 저장은 난이도별 클리어를 따로 남기지 않아 기록 밖의 악몽 클리어는 복원할 수 없다.
- P2 탑 골드 지수 증가 → 1.035 → 1.02.
- P2 탑 상한 도달 시 탑 임무 → 달성 처리(waived).
- P2 지옥 잠금 문구 → "지역 10관문 악몽 클리어", 난이도 아이콘 `difficulty-hell.svg` 추가.

## 7. BM 레인 인터페이스(결제 지급 코드는 건드리지 않음)
- 이벤트 효과는 `applyEventRewards(rewards, events, 'campaign'|'tower')` 한곳. 결제 상품 지급(`addRewards` 상품 경로)에는 적용하지 않는다.
