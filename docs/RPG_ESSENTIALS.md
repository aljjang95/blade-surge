# RPG 필수 시스템 감사와 구현 순서

2026-10-29 `[gogo-chunk:blade-rpg#essentials]`. 대표님 요청 "RPG에 해당하는 가장 필수 장치들을 기획해서 넣어 달라"(목표: 하루 8시간·3개월 하이엔드 출시)에 대한 정본. 기준 소스 `origin/main` `c2603fc`, 판정은 코드 정적 확인(UI 입구까지 확인).

비교 대상: 던파 모바일·디아블로 이모탈(핵앤슬래시), 에픽세븐(수집형), 리니지M류(방치·복귀). 장르 상위작이 공통으로 가진 "돌아올 이유" 장치를 첫날 → 첫 주 → 첫 달 유지율 영향 순으로 본다.

## 2. 구현 순서(이 레인)

영향 큰 순서. 다른 레인 소관(레벨 곡선·재화 소모처·카드 보상·캐릭터 선택·로그인·결제)은 건드리지 않는다.

| 순서 | 덩어리 | 이유 | 유지 구간 |
|---|---|---|---|
| E1 | 알림 배지 확장(여정·탑 상자·도감) + 출석 리셋 05:00 KST | 이미 있는 보상을 놓치지 않게 — 비용 최소, 효과 즉시 | 첫날 |
| E2 | 오프라인 보상 + 복귀 보상(같은 lastSeen) | 다음 접속의 첫 화면 이유 | 첫날·첫 주 |
| E3 | 신규 7일 미션 이벤트 | 첫 주 매일 목표 | 첫 주 |
| E4 | 업적(평생 누적) | 장기 목표·수집 욕구 | 첫 달+ |
| E5 | 우편 모두 받기·만료·동적 저장 + 패스 XP를 의뢰에서 | 보상 통로 정비 | 전 구간 |

보류: 길드(서버·소셜 큰 작업, 소셜 레인과 별도 설계 필요), 요일 던전(던전 클리어 루프 레인과 겹침), 상시 랭킹(소셜 레인).

## 3. 규칙

- 새 일일 리셋은 `periodAt`(05:00 KST)을 쓴다. 기기 시계에 강해야 하는 보상(오프라인·복귀)은 `endgameNow`(서버 시각 우선).
- 새 보상은 `bun run sim:90d` 밴드 안이어야 한다. 시뮬레이터가 모델링하지 않는 보상원(출석·패스 등)은 하루 기대량을 이 문서 4절에 적는다.
- UI는 메뉴 안 모달과 메뉴 점만. 전투 화면 위 팝업 없음.
- 결제 연동·유료 트랙·가격 없음.

## 4. 덩어리별 기록

(덩어리가 머지될 때마다 여기에 수치·검증을 추가한다.)

### E1 알림 배지 + 출석 경계 (PR 1)
- `src/game/reward-badges.js`: 성장 여정(단계·일일·주간 의뢰 ready) · 무한의 성 주간 상자 · 장비 도감 마일스톤 집계.
- 점 위치: 성장 여정 입구(`dot-journey`, 탑 상자 포함), 메뉴의 무한의 성, 영웅 탭(`dot-heroes`) → 가방 금고 버튼 → 금고 도감 탭. 메뉴 합산 점에 `dot-journey`·`dot-heroes` 추가.
- 출석 하루 경계: UTC 자정(KST 09:00) → `periodAt` 05:00 KST. 같은 일 번호 눈금이라 저장 이관 없음. 전환 전에 KST 05~09시에 받은 기록만 전환 뒤 같은 시간대에 한 번 더 열릴 수 있다(출석 1칸).

### E2 방치 보급 + 복귀 보상
- `src/game/idle-rewards.js`, 저장 `idle: { since, seen, comebackAt }`(서버 소유, 시각이라 정합 해시에서는 제외 — energyT 와 같음), 서버 명령 `claimIdle`·`markSeen`. 시계는 `endgameNow`(서버 시각 우선). 시계가 기록보다 뒤면 거부만 한다(당기지 않음).
- 지금은 강화석만 시간당 0.2(12시간 상한 2.4개). 골드 경로(최고 관문 골드 × goldRunShare)는 코드에 있고 비율 0 — 진행 곡선 소유는 랄프 레인이라 밴드를 다시 잡을 때 올린다. 로비 진입 시 30분 이상 쌓였으면 자동 안내, 메뉴 '보급'.
- 복귀: 마지막 접속(`seen`, 로비 30분 간격 표시)에서 7일 이상 + 3관문 이상 클리어 + 30일 쿨다운 → 보석 300·에너지 60·소탕권 5·상급 강화석 10·소환권 2.
- sim:90d: 처음 0.8로 넣었을 때 라이트 마지막 주 일 골드 29.8만 → 40.6만(+36%), 골드 소모 비율 0.25 → 0.23이라 0.4로 절반. 0.4는 시드 3 테스트에서 미드 지옥 6-10 67일(밴드 70일 이상), 0.25는 68일·최장 정체 9일(밴드 8일 이하), 0.12는 미드 D90 룬 전투력 35.9%(밴드 35% 이하, 기준선 34.4%)로 실패. 0.05는 시드 16 통과(34.6%)지만 시드 3 테스트 35.2%로 실패. 기준선이 경계(34.4%)라 어떤 추가 골드도 룬 합성으로 흘러 밴드를 넘는다 → 골드 0, 강화석 0.2로 확정(시드 3·16 모두 통과).
- 도입 전 저장은 지금부터 쌓는다(소급 없음).

### E3 신규 7일 여정
- `src/game/newbie-event.js`, 저장 `newbie: { start, claimed, final }`, 서버 명령 `claimNewbie`. 하루 3개 × 7일 = 21개, 모두 받으면 SSR 확정권 1·보석 300.
- 진척은 기존 저장 값(관문·처치·강화·레벨·소환·출석·탑·여정 단계)에서 읽는다. 기간은 시작일부터 14일(지난 날 목표도 기간 안에는 수령).
- 도입 전 저장도 오늘부터 한 번 참여(출시 기념). 보석 합계 21개 미션 350 + 완주 300.

### E4 업적
- `src/game/achievements.js`, 저장 `achievements: { claimed }`, 서버 명령 `claimAchievement`. 9계열 47단계(처치·관문·레벨·강화·소환·탑·출석·동료 수 · 여정). 단계는 차례로.
- 메뉴 '업적', 점 `dot-achieve`.

### 독립 리뷰 반영(Sonnet 1회)
- P1 가져오기·스냅샷 재수령 통로: `legacy-sanitize.js`가 반복 스냅샷은 서버 문서 값만, 외부 가져오기(계정당 1회)는 방치 시각을 서버 지금으로 다시 시작하고 여정·업적 기록은 원본을 정규화해 이어받는다(닫으면 그림자 명령이 서버에서 거절돼 패리티가 깨짐 — v1-client 테스트로 확인). 재화 주입은 기존 일일 한도가 막는다.
- newbie·achievements·idle 은 정합 해시(PARITY)에서 빼고 서버 소유(SERVER_OWNED)에만 둔다.
- P1 메뉴 안 `hidden` 버튼이 보이던 CSS 우선순위 수정.
- P1 복귀 판정을 마지막 수령 → 마지막 접속(`seen`)으로.
- P2 시계 되돌림 반복 수령, 정합 해시의 시각 필드, 읽기 경로 대입 제거, 메뉴 점 중복 합산 수정.

### 미반영·한계
- 새 보상(7일 여정·업적·복귀)은 sim:90d 골드·강화석 모형에 넣지 않았다(1회성·소량). 보석은 시뮬레이터가 소환 속도를 ECONOMY_PACE로만 보므로 BM 레인 판단 대상.
- 서버 권위(`V1_ENABLED`)에서는 새 필드가 PARITY_KEYS에 들어가 서버가 정본이 된다. 이 PR에서 라이브 서버 실측은 하지 않았다.
