# 일식 수문 심층 — 역류 밸브 4곳 봉인 (BUNDLE-07)

개인 기본 원정 일식 수문 심층(`eclipse_hydra_vault` / `deep`)의 원안 "역류 밸브 4곳 봉인"을 구현한 제품 계약이다. 일반판 역류 밸브 3개와 같은 순차 유지 엔진(`RouteObjectives`, `src/game/route-objectives.js`)을 쓰고, 일반·심층 모두 밸브 물줄기 봉인 연출(`src/game/backflow-valve-view.js`)을 얻는다. 공유 정의는 `ROUTE_OBJECTIVES.eclipse_deep`(id `eclipse_deep_backflow_seals`)과 `eclipse_standard.view`다.

## 제품 계약

- 심층 동선은 한 줄(방 0 → … → 8)이다. 밸브는 방 2(보물) → 4(정예) → 7(정예) → 5(보물) 순서로 봉인한다. 라벨: '1번 역류 밸브 · 잠긴 저수조', '2번 역류 밸브 · 맹세의 갑문', '3번 역류 밸브 · 심연 수문', '4번 역류 밸브 · 되돌아온 물길'.
- 각 밸브 구역의 적을 처치하면(정예방은 증원 2회가 모두 끝나야) 청록 빛 중심(반경 3)에서 연속 2초 머물러 봉인한다. 빛 밖으로 나가거나 일시정지하면 유지 시간이 처음부터 다시 시작된다. 피해·실패 판정은 없다.
- 4번 밸브(방 5)는 3번(방 7)으로 가는 길에 먼저 정리되고 '순서 대기'로 기다린다. 이때 방 5는 정화되지 않고 보물 보상과 정화 토스트도 봉인 때로 미뤄진다(사라지지 않는다). 3번을 봉인하면 지나온 물길로 두 구역 되돌아가 4번을 봉인한다. AUTO는 매 스텝 차례인 밸브 방을 목표로 잡는다.
- 4/4와 모든 구역 정화 뒤 보스 봉인이 풀린다. 정예방 2곳 × 증원 2회, 에너지, 해금, 보스 HP·패턴, 보상은 그대로다.
- 목표창 '역류 밸브 봉인 n/4'(차례 밸브 정리 뒤 '중심에서 2초 유지'), 결과 줄 '역류 밸브 봉인 n/4'(완료면 ' · 완료'), 결과 보고 `{ id, label, complete, progress, target: 4, rooms }`.
- 파티·균열·전술 공략·캠페인·결투에는 이 정의가 없다(`routeObjectiveForStage` null).
- 범위 밖: 세 머리 동시 예고·중앙 이탈, 지나간 물결 뒤 안전 통로(보스 리그·애니메이션 동기화 필요). content-integrity 심층 행에 남는다.

## 밸브 물줄기 봉인 연출 (일반 3·심층 4 공통)

`def.view === 'backflow-valves'`인 정의만 `RouteObjectives.prepareView`가 뷰를 만든다(가져오기 실패는 규칙에 영향 없음). 뷰는 규칙 갱신 뒤 같은 스텝 상태를 그리고, 일시정지에는 갱신하지 않으며, `stop`에서 dispose한다.

| 상태 | 기둥 | 물줄기 | 바닥 고리(반경 3 = 판정 원) |
|---|---|---|---|
| 미발견 | 숨김 | 숨김 | 숨김 |
| 차례(next) | 보임 | 전체 높이, 밝은 청록 | 밝은 청록(cueColor를 흰색 쪽으로 45%) |
| 유지 중 | 손잡이가 유지 비율만큼 돎 | 높이 1 − 유지/2초(최소 0.15) | 청록(cueColor) |
| 순서 대기 | 보임 | 높이 0.5 | 회색 0x8394ac |
| 봉인·잠금 | 손잡이 고정 | 멈춤(숨김) | 금색 0xffd060 |

- InstancedMesh 3개(기둥+손잡이 병합, 물줄기, 고리)로 draw call ≤ 3. 반투명 물줄기는 `forceSinglePass`, 고리는 앞면만 그려 한 번에 그린다. 코드 생성 geometry만 쓴다.
- 기둥·물줄기는 방 중심에서 대각선(+x, −z)으로 3.8 떨어져 유지 원과 축 방향 복도를 피한다(충돌체 없음).
- 첫 update 전까지 세 메시를 보이게 두어(인스턴스 scale 0) 출격 준비 compile에서 프로그램을 미리 만든다.
- update는 무할당이고 게임 dt만 쓴다(Math.random·Date 없음). reduced motion이면 물줄기 맥동을 멈춘다.

## 측정 방법과 BUNDLE-07 결과(2026-10-15, 클라우드 SwiftShader)

도구는 `tools/eclipse-valve-qa.mjs`(`--depth=standard|deep`, 프로필 auto·order·pause·screens, `--no-reseed`), 판정 `tools/eclipse-valve-checks.mjs`, 기준선 비교 `tools/eclipse-valve-compare.mjs`다. 공유 런타임(`tools/expedition-qa-runtime.mjs`)이 clean HEAD·dist를 묶고, fixture(저장 주입)·실제 UI(출격 카드·#btn-auto·#btn-pause·키보드)·제어 실행(testPause + 1/60 app.step, 단독 렌더)을 구분한다. 전투가 활성화되고 뷰 준비가 끝난 뒤 첫 스텝 전에 같은 시드로 `Math.random`을 다시 seed한다(새 뷰의 three.js `generateUUID`가 시드 난수를 쓰는 문제, BUNDLE-06 발견).

- 봉인 판정: 봉인마다 방 순서, 직전 연속 유지(영웅이 반경 3 안, 유지량 증가 = 게임 시각 증가, 길이 ≥ 2초 − 1/60), 그 방의 적·대기열 0, 정예방 증원 수, 순서 대기 표본(심층), 보스 봉인 해제 시점, 결과 보고·결과 줄, 목표창 문구, 뷰 인스턴스 모습(고리·물줄기 색과 높이)을 본다. 뷰의 실제 draw call은 같은 프레임을 뷰 그룹 표시/숨김으로 두 번 그려 차이로 잰다(A/B).
- 사전 선언 직렬 QA 8회(65848a7 clean dist, 시드 20261015): 7회 exit 0·실패 검사 없음·mediaGates pass. 심층 기사 151.2초·봉인 [2,4,7,5]·순서 대기 표본 177, 심층 법사 138.9초, 일반 기사 59.0초·[2,5,7], order(키보드로 방 5에서 3초 대기 = 진행 2 유지, 유지 중 이탈 = 0으로 초기화, 다시 들어가 봉인), pause(유지 중 정지에 게임 시간 불변·유지 0, 재개 뒤 새 2초로 봉인). 뷰 A/B 실제 draw call 최대 3(보고값과 일치). b07-cand-screens는 exit 1이었다(실제 결함): 방 발견이 경로 목표 갱신 뒤에 일어나 밸브가 한 스텝 늦게 보였다.
- 기준선(dbdde51) 비교: 완주 시간 비 심층 1.28·일반 0.99(상한 2.0 통과), 전체 런 50ms 초과 5/3·4/2(상한 통과). 밸브 방 첫 진입 draw call 증가는 심층 최대 +13·일반 +4로 상한 3 불합격이다. 심층은 기준선에 경로 정의가 없고 봉인 유지로 경로·시간이 갈라져 기능 외 차이를 함께 쟀고, 뷰 자체의 기여는 A/B로 최대 3이다. 일반 완주 시간 비 0.99는 재시드로 연출만 바뀐 빌드의 비교성이 돌아왔다는 근거다(BUNDLE-06 같은 비교 1.43).
- 수리와 수리 검증(사전 선언, 시리즈 판정은 바꾸지 않음): fed8fb0이 방 입장 경로만 고쳐 b07-fix-screens가 다시 exit 1이었다. 방은 0.4초마다 인접 미리보기로도 발견된다. d3501e2가 두 경로(enterRoom, peekRooms) 모두에서 뷰를 맞춘 뒤 b07-fix2-screens·b07-fix2-deep-knight 모두 exit 0·실패 검사 없음이었다.
