# Blade Surge 콘텐츠 정합성 — 미구현 원안 보존

이 문서는 현재 실행 가능한 안내로 문구를 교정하면서 원래 약속한 기믹을 보존한다. 문구 교정은 아래 기믹의 구현 완료 또는 범위 폐기를 뜻하지 않는다. 이 감사 기록은 원안 기믹의 미완료 범위를 보존하며, 아래의 실제 구현·검증 범위와 구분한다.

## 현재 실행 계약과 근거

- `src/game/expedition-combat.js`의 `buildExpeditionStage` / `buildExpeditionWorld`가 일반 12개와 심층 12개의 실제 구역, 적, 공명 여부와 증원 횟수를 선택한다. 아래는 단독 기본 원정 기준이며 별도 전술 공략(conquest), 파티, 균열의 계약이 아니다.
- `src/game/battle-base.js`의 `markCleared` / `updateExpedition`: 적을 정리한 보물방에서 `attunement: true`일 때만 중심 반경 3 안에 연속 2초 머물러 공명한다. 벗어나면 시간은 초기화된다. 보물방이 있다는 사실만으로 공명 목표가 생기지 않는다. 기존 공명에는 방문 순서 제약이 없다.
- `mechanics.reinforcements`는 전체 원정 합계가 아니라 **정예방마다** 발생하는 추가 전투 횟수다. 예를 들어 정예방 2곳 × 각 2회는 합계 4회다. 증원이 끝나야 해당 방이 완료된다.
- 일반 구역을 모두 정화하면 보스 봉인이 풀리고, 보스를 처치해 원정을 완료한다. 구역 정화나 보물방 공명은 밸브 조작, 기록 3장 수집, 별자리 복원, 왕좌 파괴 또는 궤도 정렬의 구현 증거가 아니다.
- `src/data/stages.js`의 최종 `ENEMIES` 전술과 `src/data/boss-encounters.js`의 `BOSS_SIGNATURES`가 실제 보스 공격 안내의 기준이다. 별도의 부위 애니메이션·색상 단서·무적/노출 조건은 시그니처 사용만으로 구현되지 않는다.

## 보존하는 일반 종락 계약

일반 `bellfall_crypt`의 원래 목표인 **종문 3개 순차 공명**은 현재 `src/data/route-objectives.js`, `src/game/route-objectives.js`와 전투 연결 코드에서 구현된다. 방 ID **2 → 3 → 5**의 적을 처치한 뒤 각각 중심 **반경 3, 연속 2초** 공명하며, 먼저 정리한 다른 종문은 자신의 순서를 기다린다. 종문 3개와 나머지 일반 구역이 모두 완료되어야 보스 봉인이 풀린다. 방 3은 보물방이 아니므로 보물방 수 2를 종문 수로 사용하면 안 된다.

이 안내는 일반 단독 원정에 한정한다. 심층에 역순 종문 구현이 생겼다고 간주하지 않는다. 기존 전술의 “켜진 순서를 기억해 반대쪽 안전 지대”, “마지막 공명 뒤에만 긴 반격 창”은 종문 상호작용의 실행 조건이 아니어서 제거했다. 보스 자체의 종 공격은 별도의 `bell_toll` / `bell_clap` 경고로 안내한다. 이번 문구 변경은 그 전투/종문 코드를 수정하지 않는다.
