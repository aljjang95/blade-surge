# 사냥과 성장 V2

각인 보상에서 넓은 빈 화면과 작은 선택 버튼 때문에 무엇을 얻는지 읽기 어려웠다. 승리 화면에는 성장 추천이 없었고, 시작 골드만으로 영웅 레벨을 연속 구매할 수 있어 사냥 경험치의 의미도 약했다.

## 변경한 플레이 흐름

- 원정 각인은 최대 760px, 콘텐츠 높이에 맞춘 선택창에서 고른다. 선택 대기 보상과 적용된 각인을 구분하고 종류, 효과, 강화 단계, 조합 효과를 표시한다. 명성/회복을 고르는 이야기에는 실제 보상과 선택의 결과를 함께 보여준다. 숙련과 의뢰 탐색 화면은 별도로 유지한다.
- 출격 직전 영웅 ID/레벨/경험치를 기록한다. 정산 화면은 해당 결과의 처치 XP, 완료 XP, 시작/종료 레벨과 실제 스킬 해금 정보를 표시하고 이후 재화 변경으로 사냥 요약을 다시 계산하지 않는다.
- 승리 뒤에도 현재 재화로 가능한 장비/스킬/숙련 항목으로 이동할 수 있다. 이동 자체는 재화를 소비하지 않는다. 이야기와 전리품은 펼쳐 보며, 다음 출격 버튼은 본문 스크롤 밖에 남는다.
- 빈 장비 슬롯이 있으면 다른 영웅이 착용하지 않은 전리품을 무료 비교 대상으로 먼저 안내한다. 비교 화면에서 실제 능력치 변화를 보고 장착하며, 추천 클릭만으로 장비를 옮기지 않는다.
- 골드 훈련은 현재 레벨 필요 XP의 50%를 사냥으로 채운 뒤 남은 경험치만 보충한다. 비용도 남은 XP에 비례하며 훈련 후 XP는 0이다. 기존 영웅 레벨, 경험치와 재화는 이 변경으로 초기화하지 않는다.
- 훈련 저장 실패는 레벨/XP/골드를 원복한다. 완료 보상 정산은 저장 성공 여부를 반환하며 실패 시 화면 이동을 막고 저장만 재시도한다. 보상을 다시 지급하지 않는다.
- 패배 화면 표시 뒤 숙련 이력 저장이 실패하는 순서에서도 재시도 버튼을 갱신한다. 첫 튜토리얼 중 변경한 AUTO 선택은 완료 뒤에도 버튼과 실제 전투 설정이 일치한다.

## 검증 범위

단위/통합 회귀는 훈련의 전체 레벨 경계, 기존 저장 보존, 실제 Economy 정산, 중복 클릭, 저장 실패와 재시도, 선택 큐/일시정지/포커스, 결과 45개 장비를 다룬다. 로컬 Chrome에서는 새 Lv.1 영웅의 실제 사냥과 UI 선택을 확인한다. 게임의 AUTO 기능을 사용하며 적/체력/XP/시간을 조작하지 않는다.

각인 현황/선택을 640×360, 844×390, 390×844에서, 이야기 선택을 1280×720에서 관찰했다. 최종 결과 화면과 첫 3구역의 수치 증거는 릴리스 검증 기록에서 확인한다.

GUI에서 만든 각인 이미지와 기존 Sanctuary/V3 영웅 원본을 사용한다. Blender 5.2.1 LTS에서 Sanctuary 원본 재열기/동일 GLB 재export, 영웅 5종 원본/배포 GLB 재import를 검증했다. 이 검증을 새로운 영웅 모델 제작으로 부르지 않는다.

기술 검증은 인간 플레이어의 재미 선호나 실제 모바일 기기의 GPU/발열/멀티터치 인증을 대신하지 않는다.

## 전투 시야

전경의 높은 벽과 기둥이 영웅과 적을 가리는 문제를 고쳤다. 실제 영웅 위치와 최종 카메라 위치를 기준으로 전경 건축의 윗부분을 절단하고, 0.35 높이의 벽받침과 충돌 마스크를 유지한다. 원본 GLB 재질과 영웅, 바닥, 보스 봉인에는 이 절단 재질을 적용하지 않는다. 지역 건축은 기존 방별 병합, 벽은 기존 공간별 인스턴싱을 유지한다.

같은 자세의 로컬 렌더 비교에서 전체 패스의 draw calls는 전후 136회, triangles는 776,449, geometry/texture는 각각 85로 같았다. 이는 해당 장면의 표본이며 실제 모바일 성능 향상을 의미하지 않는다. 독립 검토에서 Three r170의 뷰 공간 판정 576건과 자원 소유권/카메라 순서를 확인했다.

세로 HUD에서 보스 직행 버튼이 나타나도 일시정지가 다음 줄로 밀리지 않는다. 실제 320px 화면에서 다섯 버튼은 각각 44×44px이며, 콤보/연속 처치와 시점 버튼을 성장 정보 밖으로 옮겼다.

## 최종 실제 플레이 검증 — 2026-09-21

동일한 새 저장으로 첫 세 구역을 실제 AUTO 사냥했고, 세 번째 구역에서는 해금된 Q 스킬도 직접 눌렀다. 적/HP/XP/시간을 주입하지 않았다. 구역 사이에는 실제 획득 장비를 무료 장착하고, 표시된 비용 127골드와 243골드로 각각 한 번 훈련했다.

| 구역 | 시작 → 종료 레벨 | 처치 XP | 완료 XP | 처치 | 전투 시간 | 정산 장비 |
|---|---|---:|---:|---:|---:|---:|
| 1-1 | 1 → 5 | 479 | 165 | 195 | 167.9초 | 37 |
| 1-2 | 6 → 8 | 486 | 184 | 190 | 143.8초 | 41 |
| 1-3 | 9 → 11 | 882 | 205 | 278 | 210.9초 | 53 |

세 번째 구역에서 성쇄·결박이 해금됐고 실제 발동 상태와 쿨타임을 확인했다. 스킬북 E로 이동한 뒤 Q로 복원해도 골드 16,177은 유지됐다. 추가 카메라 검사 전투를 UI로 포기한 결과는 별도의 패배 경로 검증으로 분리했다.

최종 통합 검사: 1,024 pass / 1 기존 진단 skip / 0 fail, 113,819 expect 호출. 타입 검사와 production build 통과. 성장/정산, 절단 렌더, 세로 HUD에 독립 검토를 수행했다. 마지막 CSS는 실제 320×568, 320×740, 390×844에서 버튼 크기와 조작 겹침을 측정했다.

결과 화면 844×390 및 640×360 버튼은 57px, 390×844는 64px였다. 640×360에서 실제 전리품 37개를 펼쳤을 때 본문은 255px/스크롤 1,171px이고 하단 버튼 영역은 화면 안에 유지됐다. 실패 저장을 통제된 검사로 주입한 뒤 실제 재시도 버튼을 눌러 영웅/골드/장비 수가 같고 completeStage 재호출이 0회임을 확인했다.

운영 후검증에서는 포기 결과에 처치 XP 111이 표시된 뒤 남은 타격이 실제 XP를 123으로 올리는 기존 종료 경계 결함을 발견했다. 전투가 종료되면 늦은 타격과 처치 콜백이 XP·도감·드랍을 추가하지 않도록 차단했다. 수정 전 실패하는 회귀 2개로 확인했고, 사망 후 부활 대기의 처치와 승리 연출·기존 드랍 수거는 유지한다. 추가 독립 검토에서 P1/P2 발견 사항은 없었다.
