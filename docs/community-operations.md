# 커뮤니티 운영 설계 — 디스코드·게시판·명예 구조

2026-10-19, 대표님 요청("디스코드? 방 운영해야하나? 이슈 버그 업데이트 희망 아이디어 공유 이런것들도 필요할꺼같아")에 대한 결정과 운영 방법이다. 기능 구현은 packages/tll-social, 화면 설계는 work/blueprint의 community-1 묶음(결정 D13~D16)에 있다.

## 결론

디스코드 공식 서버는 연다. 다만 원본은 게임 안 '소식·제보' 게시판이다. 게임을 켠 사람은 누구나 버그·건의를 남길 수 있어야 하고, 디스코드를 쓰지 않는 이용자(국내 모바일 이용자 대부분)도 같은 창구를 쓰게 하기 위해서다. 게시판에 올라온 버그 제보·업데이트 희망·아이디어와 서버 최초 정복 기록은 웹훅으로 디스코드에 자동으로 올라간다. 운영자는 디스코드에서 알림을 보고, 답변·상태 변경은 게임 안 관리자 화면에서 한다. 그러면 기록이 한곳에 모이고 게임 이용자도 답변을 본다.

네이버 카페·카카오 오픈채팅은 국내 이용자 접근성이 더 좋지만 글 자동 등록 API가 없거나 제한적이라 수작업이 생긴다. 동시 접속이 꾸준히 수백 명을 넘으면 그때 공식 카페(공지 미러링용)를 추가한다.

## 디스코드 서버 구성(권장)

| 분류 | 채널 | 용도 | 자동화 |
|---|---|---|---|
| 안내 | #공지 | 운영 공지, 점검 | 운영자 작성 |
| 안내 | #패치노트 | 업데이트 내역 | 배포 때 운영자 작성(추후 자동화 후보) |
| 안내 | #규칙 | 커뮤니티 규칙, 신고 방법 | 고정 |
| 명예 | #명예의-전당 | 서버 최초 정복·칭호 획득 | 게임 웹훅 DISCORD_WEBHOOK_FAME |
| 제보 | #버그-제보 (텍스트) | 게임 게시판의 버그 제보 | 게임 웹훅 DISCORD_WEBHOOK_BOARD |
| 제보 | #건의-아이디어 (텍스트) | 업데이트 희망·아이디어 | 같은 웹훅(분류 표시) |
| 커뮤니티 | #자유-채팅, #파티-모집, #질문-답변, #스크린샷 | 이용자 대화 | 없음 |

역할: 개발자, 운영진, 창립 모험가(가입 순번 1000번까지), 최초 정복자, 인증 모험가(구글 연동). 게임 칭호와 디스코드 역할을 자동으로 맞추는 봇은 다음 단계 후보다(계정 연결 절차가 필요해 이번 범위 밖).

## 웹훅 연결 방법

1. 디스코드 서버 설정 → 연동 → 웹후크 → 새 웹후크. #명예의-전당용 하나, #버그-제보용 하나를 만든다.
2. 웹후크 URL은 비밀값이다. 채팅·Git·문서에 붙여 넣지 않는다. Worker 비밀로만 등록한다:
   'npx wrangler secret put DISCORD_WEBHOOK_FAME' / 'npx wrangler secret put DISCORD_WEBHOOK_BOARD' (blade-surge Worker).
3. 등록하지 않으면 해당 자동 전달만 꺼지고 게임 기능은 그대로다.
4. 게시판 웹훅은 사용자 문자열의 @everyone·@here·멘션을 무력화해서 보낸다(allowed_mentions 비움).

## 관리자 지정

게임에서 커뮤니티 → 내 프로필 → '내 ID 복사'로 얻은 playerId를 Worker 변수 SOCIAL_ADMIN_IDS(쉼표 구분)에 넣는다. 관리자는 게시판 상태(검토 중·반영 예정·반영 완료·반려), 개발자 답변, 글 숨김, 음소거·이용 정지, 부정 기록 회수를 할 수 있다.

## 운영 리듬(권장)

- 버그 제보: 48시간 안에 '검토 중' 표시. 재현되면 '반영 예정', 배포 후 '반영 완료'와 패치노트 링크.
- 아이디어: 매주 공감 상위 3개에 개발자 답변. 반영하면 글쓴이 이름을 패치노트에 적는다(참여 자부심).
- 서버 최초: 칭호 구간 기록이 나오면 게임 전체 공지와 디스코드에 자동으로 올라간다. 새 던전을 추가할 때마다 새 최초 경쟁이 열린다.
- 신고: 같은 사람을 1시간 안에 3명이 신고하면 10분 자동 음소거. 운영자는 신고 목록에서 정지 여부를 판단한다.

## 자부심 구조

- 창립 모험가 No.: 가입 순번이 영구 표시된다. 1000번까지 '창립 모험가' 칭호.
- 던전별 서버 최초 정복 순위: 1위 '최초 정복자', 2~10위 '선구자', 11~100위 '개척자'. 순위는 영구 기록이며 명예의 전당 시상대에 남는다.
- 최단 기록: 서버가 잰 시간(출격 티켓 발급~클리어 보고)으로 순위를 매긴다.
- 전 지역 정복자: 모든 던전을 깬 사람. 서버 정복 순위는 깬 던전 수, 같으면 먼저 달성한 순서.
- 대표 칭호는 채팅·파티·친구 목록에서 이름 옆에 보인다.

## 부정 방지의 한계(정직한 설명)

전투는 각자의 기기에서 계산되므로 서버가 승패 자체를 검증하지는 못한다. 대신 출격 때 서버가 발급한 티켓이 있어야 하고, 던전별 최소 시간보다 빠르거나 2시간을 넘긴 보고, 같은 티켓의 중복 보고는 기록하지 않는다. 의심 기록은 관리자가 회수할 수 있고, 구글 연동한 기록에는 인증 표시가 붙는다. 랭킹에 실물 보상을 거는 단계가 오면 서버 판정 전투나 리플레이 검증이 먼저 필요하다.

## 계정(구글 로그인)

게스트로 바로 시작하고 구글 연동은 기록 보호용 선택 기능이다(결정 D14). 계정 연결은 친구·칭호·커뮤니티 기록 복구를 위한 것이며, 게임의 로컬 진행 저장까지 자동으로 옮겨 주는 기능은 아니다.

웹 OAuth 클라이언트 `Blade Surge Web`은 이전 인앱 브라우저 작업에서 생성했다. 공개 클라이언트 ID는 `898058209232-qr2isup4rafe3fhhgt5e1vvntu267sf3.apps.googleusercontent.com`, 등록한 JavaScript 원본은 `https://blade.tllhouse.com`이다. 서버 `GOOGLE_CLIENT_IDS`와 웹 코드가 같은 ID를 사용한다. 클라이언트 보안 비밀번호는 이 방식에 필요하지 않으며 취득·저장하지 않았다.

One Tap만 호출하면 구글 세션·쿨다운 등의 이유로 명시적 클릭에서도 안내가 뜨지 않을 수 있어, 공식 `renderButton`의 팝업 흐름을 사용한다. 구글 버튼은 한국어로 표시하고 취소·Escape·시간 초과·중복 클릭을 처리한다. ID 토큰은 서버의 서명·발급자·대상·만료 검증에만 전달하며 브라우저 저장소나 로그에 남기지 않는다. 참고: [구글 공식 버튼 안내](https://developers.google.com/identity/gsi/web/guides/display-button).

2026-10-21 재개 시점의 미확인 사항:

- 이전 기록에서는 OAuth 동의 화면이 테스트 중이었다. 앱 게시, 개인정보처리방침 URL 저장, 실제 계정 연결·새 기기 복구 성공은 현재 콘솔과 실제 구글 인증으로 다시 확인해야 한다.
- 개인정보처리방침 공개 주소는 `https://blade.tllhouse.com/privacy.html`이다. 약관 URL은 실제 약관 페이지를 확인한 뒤 등록하며 임의 주소를 넣지 않는다.
- Capacitor Android의 Credential Manager 연결은 아직 구현·검증되지 않았다. 웹 클라이언트를 만들었다고 Android 앱 로그인이 지원되는 것은 아니다. 스토어별 별도 증거가 필요하다.
- 현재 재개 세션에는 인앱 브라우저 제어 도구가 노출되어 있지 않아 구글 콘솔 변경과 디스코드 생성은 실행하지 못했다. 이전 기록에서 디스코드는 로그인 화면까지 확인했고 승인된 로그인 경로는 찾지 못했다. 대표님에게 raw 비밀번호·웹훅 URL을 채팅으로 요청하지 않는다.

## 디스코드 개설 상태와 이어갈 순서

서버·초대 링크·웹훅은 아직 생성 완료로 확인되지 않았다. 게임 게시판과 웹훅 전송 코드는 준비되어 있지만, 실제 디스코드 도착까지 확인해야 운영 연결 완료다.

1. 인앱 브라우저의 기존 계정 세션으로 디스코드에 진입하고 소유자 계정을 확인한다.
2. `TLL 게임 라운지` 서버에 게임별 분류를 만들고 블레이드 서지 채널을 위 표대로 구성한다. 다른 게임 추가 시 게임별 초대·웹훅·운영자 범위를 분리한다.
3. 자동 전달 대상은 `#명예의-전당`과 `#버그-제보` 텍스트 채널로 만든다. 현행 웹훅 본문에는 포럼 필수 스레드 정보가 없으므로 포럼 채널을 자동 전달 대상으로 지정하지 않는다. 아이디어는 같은 제보 웹훅의 분류 표시로 전달한다.
4. 공개 초대 링크만 `SOCIAL_CONFIG.discordInvite`에 넣고, 웹훅 URL은 Worker 비밀 `DISCORD_WEBHOOK_FAME`, `DISCORD_WEBHOOK_BOARD`에만 직접 등록한다. 웹훅 비밀을 문서·PR·로그에 남기지 않는다.
5. 테스트 제보와 명예 알림이 올바른 채널에 도착하고 멘션이 비활성화되는지 확인한 뒤 운영 연결 상태를 갱신한다.
