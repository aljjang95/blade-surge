## 만든 방법

- 문구: 코드와 문서(`PRD.md`, `README.md`, `docs/`, `src/data/*`, `config/store-providers.json`)에서 실제로 있는 기능만 옮겼다.
  길이·금칙어 검증은 `node tools/store-listing-check.mjs`.
  - 광고: 구글플레이 flavor에 AdMob 전면 광고 SDK가 있고, 광고는 로비의 '광고 · 구매 복원' 메뉴에서 이용자가 직접 누를 때만 나온다(`src/ui/store-access.js`). 그래서 "광고가 포함될 수 있습니다"로 적었다. AdMob 승인 상태는 `adsApproval: pending`이다.
  - 결제: 실제 결제는 아직 연결 전이라 유료 상품·VIP·패스를 광고하지 않았다. 소환(가챠) 요소는 실제로 있으므로 확률 정보 위치를 안내했다.
  - 협동(파티)은 기본 솔로 로비에서 숨겨져 있어 쓰지 않았다.
- 아이콘: 기존 앱 아이콘 `public/img/icon.png`(= `android/.../drawable-nodpi/bladesurge_icon.png`, 같은 SHA)을 픽셀 그대로 알파 채널만 붙여 저장 (`node tools/store-graphics.mjs --only=icon`).
- 스크린샷: `node tools/store-screenshots.mjs --sets=phone,tablet7,tablet10`
  - Vite 개발 서버 + Playwright Chromium(SwiftShader). 뷰포트 960x540 / 960x600 / 1280x800 × DPR 2.
  - 입력은 실제 터치(시작, 출격, AUTO, 궁극기, 메뉴, 장비 장착). 시간만 `app.step(1/60)`으로 결정적으로 진행한다.
  - 고정값: 새 저장, 검성 Lv.3, 출석 팝업·튜토리얼만 건너뜀, Math.random 시드 고정. 위치·체력·피해·드랍·승리는 건드리지 않았고 UI에 오버레이·캡션을 얹지 않았다.
  - 전투 장면은 스킬 이펙트(스파크·이펙트 오브젝트 수)가 정점인 순간, 보스 장면은 궁극기 터치 0.53초 뒤.
  - 세 세트가 같은 시드를 쓰므로 같은 순간을 찍는다(화면 비율만 다름).
- 피처 그래픽: `node tools/store-screenshots.mjs --sets=keyart`로 HUD를 숨긴 실제 전투 장면(3072x1500)을 찍고, `node tools/store-graphics.mjs --only=feature`가 영웅이 오른쪽에 오게 잘라 자체 서체 Blade Sans KR(OFL)로 타이틀을 얹어 1024x500으로 줄인다. 원본 캡처는 `work/`(git 무시)에 있다.

## 알려진 약점

- 아이콘과 타이틀 화면의 일러스트는 프로젝트의 기존 이미지 생성 자산이다(README의 에셋 출처 표기 참고). 새로 만들지 않았다.
- 전투 화면의 궁극기 장면은 이펙트가 밝게 번져 영웅 형태가 흐릿하다(게임의 실제 연출).
- 전투·보스 화면에 튜토리얼 안내 문구가 일부 남아 있다(실제 UI).
- 소프트웨어 렌더(SwiftShader) 캡처다. 실기기 화질·성능 증거가 아니다.
- 스크린샷 24장 합계 약 60MB라 저장소 용량을 늘린다. 필요하면 태블릿 세트만 빼도 된다.

## 인앱 상품

- 준비된 것: 카탈로그(`src/shared/iap-catalog.js`)의 판매 상품 4개(`remove_ads_v1` 4,900원, `starter_pack_v1` 1,200원, `season_pass_s1` 9,900원, `monthly_card_v1` 월 5,900원 구독)의 Play 등록 정의 `iap-products.json`(카탈로그에서 `node tools/play-iap-register.mjs --write-json`으로 생성, 테스트가 일치 검사)와 등록 스크립트 `tools/play-iap-register.mjs`. 보석 팩 3종은 `paid-gem-split` 게이트라 제외.
- 현재 Play에는 등록된 상품이 없다(새 API `oneTimeProducts`·`subscriptions` 조회가 모두 빈 목록). 구 API `inappproducts`는 막혀 있어 쓰지 않는다.
- 기본 실행은 dry-run이다(요청 출력만, 쓰기 없음). `NODE_USE_ENV_PROXY=1 node tools/play-iap-register.mjs --probe`는 읽기 GET 두 개로 현재 등록 상태만 본다.
- 실제 등록은 대표님 확인 뒤에만: `node tools/play-iap-register.mjs --apply --i-have-owner-approval` (두 플래그가 모두 있어야 한다. 클라우드 세션에서는 `NODE_USE_ENV_PROXY=1` 필요). 실패하면 그 요청에서 즉시 멈춘다.
- 등록 전 확인할 것:
  - 가격: 카탈로그 값은 후보다(`docs/BM_DESIGN.md` 3장). 등록하면 KR 판매가로 공개된다.
  - 세금 분류(`taxAndComplianceSettings`): 스크립트는 값을 넣지 않는다. 콘솔에서 상품 유형별 분류를 확인한다.
  - 환불 문구: 상품 설명과 스토어 문구에 환불·구독 해지 안내가 맞는지, 월정액 설명(자동 갱신, 언제든 해지)이 약관과 일치하는지.
  - 스크립트 안 `apply 전 확인` 주석이 붙은 필드(`legacyCompatible`, `batchUpdateStates` 요청 객체명, 구독 `benefits` 필수 여부)는 첫 실행 전에 공식 문서로 재확인한다.
