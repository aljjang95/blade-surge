# 지역 마을 해금 — 던전은 그 지역 마을이 열려야 보인다 (2026-10-24)

대표님 피드백(운영 실제 플레이): "마을에 잿빛이 바로 있는 게 아니라, 1스테이지를 다 깨면 새로운 마을로 가서 생성되게 해 달라."

## 무엇이 문제였나 (코드로 확인)

- 새 저장 Lv.1 첫 마을 'REGION 01 종지기 정원 마을' 로비 카드 줄이 `ALL_DUNGEONS` 20곳 전부를 순서대로 깔았다(`dungeon-journey.js` → `dungeon-landing.js` → `citadel-command.js`). 둘째 카드가 **잿불 금고**(`ember_vault`, 테마 forge, Lv.2)다. '다른 던전 4/20'.
- 영웅 뒤 3D 관문은 서비스 마을 `oathhold` 의 배정 6곳(`towns.js`: 유리 정원 · 일식의 심연 수문 · **잿불 금고** · 종락의 지하 회랑 · 뿌리잠식 동굴 · 공명목 수목원)이었다. 카메라에 4곳이 보인다.
- 지휘 판단('잿빛' = 잿불 금고와 그처럼 아직 갈 단계가 아닌 던전)이 맞다. 잿불 금고는 이름·재료(잿불 핵)·테마(forge)·기반 장(2)이 모두 2지역 '불씨 용광로 마을'과 같은데 1지역 마을에 처음부터 서 있었다. 같은 화면의 '잿'이 들어간 다른 이름(재의 밀물 수문, 재벼림 지하 제련소)도 모두 2지역 던전이며 카드 줄에 처음부터 보였다.
- 수정 전 재현(같은 시드: 새 저장, 1280×720): 카드 20장, `다른 던전 4/20`, 관문 `glass_garden, eclipse_hydra_vault, ember_vault, bellfall_crypt, rootbound_grotto, hollowbell_arboretum`.

## 규칙

1. 던전마다 캠페인 지역(1~6)을 배정한다(아래 표, `src/data/region-dungeons.js`).
2. 지역 X 던전은 캠페인 (X-1)-10 을 처음 클리어해 지역 X 마을이 열린 뒤에 **보이고 열린다**(`latestTownChapter(progress)`). 지역 1은 처음부터.
3. **소급 보존**: 입장·클리어 기록(기본 승리, 심층 승리, 진행 중 입장권, 원정 기록의 던전 경로, 이관 때 고정한 목록)이 있는 던전은 지역이 잠겨 있어도 절대 숨기지 않는다.
4. 숨은 던전은 입장도 막힌다(`ExpeditionEconomy.dungeonAccess` 사유 `1-10 클리어 시 새 마을 「불씨 용광로 마을」에서 열림`). 레벨 조건은 그대로 따로 본다. 심층은 기존 캠페인 X-10 조건이 항상 지역 해금보다 뒤라 기존 문구를 먼저 보인다.
5. 표면별 노출
   - 로비 카드 줄 · 추천: 보이는 던전만. 현재 로비 마을 지역의 던전이 먼저, 그다음 다른 열린 지역, 마지막에 소급 보존 던전. 추천은 '입장 가능한 첫 미정복 → 첫 미정복 → 입장 가능한 첫 던전' 순(숨은 던전은 후보가 아님). 카드에서 숨은 던전을 고른 선택은 무시한다.
   - '다른 던전 N/M': M 은 보이는 던전 수.
   - '다른 던전' 목록(원정 목록 · 여정 지도 · 심층 탭): 보이는 던전 + **다음 지역 하나만** 잠금 줄(`잠긴 다음 마을 · REGION 02 / 불씨 용광로 마을 / 1-10 클리어 시 새 마을에서 던전 6곳이 열립니다`).
   - 3D 관문 · 마을 둘러보기 · '마을 일 · 던전' 목록: 지금 로비 마을(캠페인 지역)의 던전 + 아직 마을이 열리지 않은 소급 보존 던전(최대 6). 처음부터 광장 관문이 없던 컨셉 던전(석양 황동 채석장 · 빙하 조수 분지)은 카드 · 목록에만 있고 관문은 서지 않는다(입구 디자인이 없어 관문을 지으면 로비 부팅이 실패하는 것을 QA에서 재현해 막았다). 그래서 2지역 관문은 5곳, 4지역은 2곳이다.
6. 1-10 첫 클리어 연출: 결과 화면 1.2초 뒤 위쪽 띠 `새 지역 해금 · 불씨 용광로 마을 / 로비로 돌아가면 새 마을로 이동합니다`(기존) → 로비 복귀 시 마을 색 장막이 가장자리로 걷히고(1.3초, 입력 막지 않음, 동작 줄이기면 생략) 위쪽 가장자리 띠 `REGION 02 · 새 마을 도착 / 불씨 용광로 마을 / 새 던전 6곳이 열렸습니다`(5.2초) → 새 던전 관문이 빛기둥과 함께 땅에서 하나씩 솟아오른다(0.9초 뒤 시작, 0.45초 간격, 1.5초 상승 + 0.8초 빛 사그라짐). 플레이 영역에 창·카드를 띄우지 않는다. 앱이 결과 전에 닫혔다면 다음 로비 진입에서 같은 띠를 한 번 보이고, 이미 지은 광장을 한 번 다시 지어 새 관문을 같은 방식으로 솟아오르게 한다. 상승 시간은 실제 시간 기준(프레임당 최대 0.25초 진행)이라 느린 기기에서도 약 5초 안에 끝난다.

## 배정표

기준은 각 던전이 처음부터 갖고 있던 기반 장(`expansion.js dungeon(id, name, theme, ch, ...)` 의 ch)과 테마다. 예외 한 곳만 옮겼다.

| 지역 · 마을 | 던전 (minLevel) | 근거 |
|---|---|---|
| 1 종지기 정원 마을 | 유리 정원(1) · 종락의 지하 회랑(2) · 뿌리잠식 동굴(3) · 공명목 수목원(4) | 기반 장 1, 정원·종 테마 |
| 2 불씨 용광로 마을 | 잿불 금고(2) · 재의 밀물 수문(2) · 재벼림 지하 제련소(2) · 슬래그워터 제련소(5) · 불씨항 건선거(6) · 석양 황동 채석장(1) | 기반 장 2, forge 테마 |
| 3 서리 서고 마을 | 별빛 서고(3) · 밤유리 관측소(3) · 성운의 레비아탄 첨탑(3) · 오로라 빙정호(7) | 기반 장 3, frost 테마 |
| 4 별잠 등대 마을 | 일식의 심연 수문(1) · 빙하 조수 분지(1) · 녹청의 성역(4) | 기반 장 4, 조수·심연 |
| 5 새벽 성문 마을 | 흑사막 환영 분지(5) · 왕관붕괴 빙하(8) | 기반 장 5 / **예외**: 왕관붕괴 빙하는 기반 장 3이지만 이름·'빙하의 판결' 왕관 기믹이 5지역(왕관)과 맞고 Lv.8 이라 3지역에 두면 3지역이 5곳으로 무거워진다 |
| 6 함께 잇는 귀환 마을 | 혜성의 유성 요새(6) | 기반 장 6 |

지역이 열려도 기존 레벨 조건은 그대로다(예: 1-10 직후 탐험 Lv.1 이면 2지역 중 석양 황동 채석장만 바로 입장, 나머지는 Lv 표시로 잠김).

## 서비스 마을(3) ↔ 캠페인 지역 마을(6)

- **고른 안: 층 분리 매핑.** 캠페인 지역 마을(6) = 어떤 던전이 서는가(던전 층). 서비스 마을(3, `towns.js` oathhold/emberport/starcrest) = 광장 배치 · 상인 · 교관 · 의뢰 · 이동석(서비스 층). 광장 관문은 서비스 마을과 무관하게 지금 로비 마을 지역의 던전이 선다(`TownUI.dungeonIds` → `regionDungeonState(save).gateIds` → `setTownDungeonIds`). 서비스 마을 해금 조건(이전 서비스 마을 배정 던전 클리어 수 + 영웅 레벨)과 상점 · 교관 데이터는 바꾸지 않았다(상점 밸런스 레인 소유).
- 다른 선택지
  - 둘을 하나로 합치기(6마을이 상점 · 교관까지 소유): 상점 · 교관 · 의뢰 데이터와 저장(`towns.unlockedTownIds`), 상점 밸런스 레인과 정면으로 겹치고 범위가 커서 이번 덩어리에서 제외.
  - 서비스 마을 배정 그대로 두고 가시성만 거르기: oathhold 1지역에서는 우연히 4곳이 맞지만 2지역에 들어가면 관문이 잿불 금고 1곳만 늘고 나머지 2지역 던전은 emberport(Lv.5 + 4곳 클리어)에 묶여 '새 마을에 가면 새 관문'이 성립하지 않는다.
- 남은 정리: 서비스 마을 해금 조건은 여전히 원래 배정(`towns.js dungeonIds`)의 클리어 수를 센다. 기존 저장은 보통 이미 열려 있고 새 저장은 1지역 4곳으로 emberport 조건(4곳)을 채울 수 있어 막히지 않지만, 문구가 지역 마을과 따로 논다. 상점 레인과 합의해 다음 덩어리에서 정리한다.

## 저장 이관

- 새 최상위 필드 `regionGate: { v: 1, kept: string[] }`. 새 저장은 `kept: []`.
- `regionGate` 가 없는 기존 저장은 정규화(`save-base.js` → `normalizeRegionGate`)에서 **그 순간 남아 있는 던전 기록 전부**를 `kept` 에 한 번 고정한다. 원정 기록(`masterworks.history`)은 최근 20개만 남아 패배만 있던 던전이 나중에 밀려나도 숨지 않게 하기 위해서다. 이미 이관된 저장은 `kept` 를 검증(알 수 없는 id·중복·형식 제거)만 한다. 순수 · 멱등.
- 진행 · 재화 · 별 · 마을(`campaignTown`) 값은 바꾸지 않는다. 별 기록만 있는 옛 저장은 기존 정규화가 별에서 `progress.unlocked` 를 복원하고 그 값으로 지역이 열린다.
- 이관 이후 새로 생기는 기록은 지역이 열린 던전에서만 생길 수 있다(숨은 던전은 입장이 막힘). 그래서 `kept` 는 다시 계산하지 않는다.

- `regionDungeonState(save)` → `{ latest, current, entries, byId, visibleIds, teaserIds, teaser, gateIds }` — 보이는 순서 · 예고 줄 · 현재 마을 관문.
- `visibleDungeonIds(save)` → `Set`.

- 인스턴스 편의: `app.expedition.dungeonVisibility(id)`, `app.expedition.regionDungeons()`. 입장 가능 여부(레벨 포함)는 기존 `app.expedition.dungeonAccess(id, { depth })` 가 지역까지 함께 본다.
- 배정표: `src/data/region-dungeons.js` 의 `DUNGEON_REGION`, `dungeonRegion(id)`, `regionDungeonIds(chapter)`.

## 남은 것

- 일일 임무 '오늘의 원정지'와 균열 회전(`DUNGEONS[day % 3]` = 유리 정원 · 잿불 금고 · 별빛 서고)은 새 저장에서 3일 중 2일이 지역 잠김 던전을 가리킨다(수정 전에도 Lv.2·3 잠금이었다). 회전을 '보이는 던전' 기준으로 바꾸는 일은 임무 · 경제 소유 범위라 남긴다.
