# 생산 런타임 셰이더 연결 검증

성공한 프로그램마다 Three의 상세 진단 로그를 읽던 생산 런타임을 연결 상태의 최초 1회 검증으로 바꾼다. 연결 실패는 진단을 읽고 예외로 거절하며 성공만 WeakSet에 저장한다. 같은 수의 프로그램이 새 객체로 교체되는 경우도 검사한다. context loss는 별도 복구 경로를 위해 검사·캐시를 미룬다. 개발 모드는 Three의 상세 진단을 그대로 유지한다.

프로덕션 실제 WebGL: 기사/mid, 마법사/low, 궁수/reduced에서 127/118/127개의 현재 프로그램이 모두 연결됐고, 실제로 만든 미연결 WebGL 프로그램을 거절했다. 키보드 스킬·MP/CD, 링 draw 64→32, 경고 불변·소멸·중지·재시작도 통과했다. 개발 Vite의 실제 부팅→로비→전투→J키 공격에서 상세 성공 로그가 활성화되고 검증된 프로그램이 존재함을 확인했다. 일반 페이지 오류와 요청 실패 0.

타입 검사·빌드 통과, 테스트 1247 pass / 2 skip / 0 fail. 새 단위 검사는 성공 캐시, 실패 거절/재검증, 동일 개수의 새 프로그램, context loss 복구를 검증한다. 기존의 탐색 진단과 Windows DPAPI skip을 유지했다.

CPU 진단에서 기존 소스는 getProgramInfoLog 약 7.69초/getShaderInfoLog 약 6.74초가 샘플링됐다. 수정 후 해당 성공 로그의 샘플링 시간은 0이고 연결 질의 약 4.04초는 남았다. 진단 완주 평균 스텝 2.11→1.05ms는 단일 프로파일 비교이며 출시 승인·물리 GPU FPS 근거가 아니다. 자세한 raw 프로파일은 별도 work 경로에 저장했다.

이전 단일 패스 후보 9301c3c의 정식 5쌍은 pair 2/3/4 회귀로 실패했다. baseline draw426/440 초과도 보존했다. 전체 원본과 판정은 rejected-single-pass-series.json이다. PR #87은 실패를 명시한 draft이며 머지·배포하지 않았다. 이 변경은 후보 소스를 바꾼 다음 회전으로, 이전 실패를 지우거나 통과하는 표본을 선별하지 않는다.

이 자료는 freeze 전 dirty 빌드의 실제 소스 해시를 명시한다. 정식 승격은 새 정확한 깨끗한 SHA로 사전 등록·빌드한 전체 5쌍 판정을 따른다. 기존 baseline draw427의 원본 해시와 출처를 유지하는 repair 경로만 사용하며 head 기준·상대 회귀 기준은 변경하지 않는다.

맵·전투 판정·카메라 이동·진행/경제를 이 수정으로 변경하지 않았다. 실기기·오디오·장기 플레이 검증과 AAA 완성은 미확인이다. 중첩 발광으로 영웅을 가리는 문제도 별도다.

이전 진단 도구의 고정 출력 경로 때문에 33f2188의 비승격 CPU 프로파일 하나가 덮어써졌다. 정식 측정 원본은 영향이 없으며 9301c3c의 새 프로파일은 별도 보관했고 이후 도구의 프로파일 경로를 각 출력 ID에 연결했다. 이전 프로파일 원본이 복구됐다고 주장하지 않는다.
