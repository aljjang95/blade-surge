## 플레이 확인 방법과 범위

IAB localhost5194의 새 세이브에서 UI로 퀘스트, 전직, 던전 진입, 제작, 장착, 강화, 정련을 실행했다. 일부 긴 전투는 `app.step(1/60)`으로 동일 게임 엔진의 시간을 진행해 검증했다. 적 HP·공격력·승리 플래그·재료를 임의로 주입하지 않았다. 정산창에 나온 시간에는 테스트 중 대기 시간이 포함될 수 있어 클리어 속도 벤치마크로 사용하지 않는다.

유리 정원 수호 기사16처치/최대36콤보, 잿불 금고 추적자15처치/80콤보, 별빛 서고 추적자12처치/75콤보를 확인했다. 무료 결투에서 보스 전리품이 과잉 지급되는 문제를 실제 플레이에서 발견해 전투 생성·수거와 경제 정산 양쪽에서 차단했다. 수정 후 챔피언 정산 차이로 재검증했다.

초기390×844 원정 화면의 가로 넘침 검증 후, 대표님 추가 지시에 따라 별도 전체 화면을 제거하고 기존 게임 모험 메뉴 내부로 통합했다. 상단 재화와 하단 메뉴를 유지하며 캠페인·던전·결투·공방·전직·퀘스트를 같은 게임 화면에서 관리한다. R3F 공방 미리보기는 low 품질에서 정적 이미지, reduced-motion에서 정지한다.

최종 배포용 빌드는 localhost5195에서 열었다. 유리 정원 화면, WebGL2=true, 새 Flow 파일3개 정상 로드, 콘솔 error0을 확인했다. 던전 시작 지점110프레임의 실제 requestAnimationFrame 간격은 중앙값5.60ms, p95 5.70ms였다. 이는 이 데스크톱/IAB의 짧은 측정이며 모바일 성능·격전·발열 검증이 아니다.

## 자동 검사와 남은 경계

- `bun run check`: Bun1.4.2,212 pass/0 fail,8073 assertions, 타입 검사 및 Vite 빌드 성공. 게임 내부 메뉴 및 갑옷 착용 통합 후 검사다.
- 저장 실패·백업 실패·중복 정산·잔여 입장권 복구·소모품 원자성·무료 결투 보상 경계를 자동 검사했다.
- GUI 이미지10개 총 WebP2,656,324바이트. 신규 Flow BGM1,016,879바이트. 생성물은 CC0라고 표시하지 않으며 기존 KayKit/Quaternius/Kenney CC0와 출처를 구분한다.
- 초기 IAB 버전 조회 차단 이후, 정상 배포 도구 경로에서 기존 라이브 SHA068e1fc와 기준 커밋 일치를 확인했다. PR14 배포 후에는 운영 SHA a7fdba6, dirty=false, 단일100% 배포 및 잠금 해제를 확인했다. 운영 IAB에서 내부 던전·영웅 착용 화면, WebGL2, 콘솔 오류0건과 입장 영상 재생·건너뛰기를 확인했다.
- 실제 청음·소리 선호·모바일 실기기 조작/발열은 확인하지 않았다. 사운드 파형·디코드·로드 증거를 주관적 타격감 승인으로 바꾸지 않는다.
- 결투장의 구현 범위는 로컬 AI 대전이며 실시간 PvP·서버 랭킹은 포함하지 않는다.

## 추가 지시 반영: 게임 내부 메뉴와 방어구

기존5지역 맵을 AI3D 작업본과 비교했다. region-architecture.js, region-hazards.js, lobby-hall.js, arena.js의 내용이 같으며 추가로 가져올 맵 변경은 없다. 현재 world.js 차이는 이번 원정용 방 역할과 배치 확장이다. 캐주얼 얼굴·몸을 유지하고 이 맵을 그대로 사용한다.

영웅 메뉴 안에 실제 모델과 장착 장비를 렌더하는 R3F 착용 창을 추가했다. 기존 방어구16종은 아이템별 색·재질·의상 형태를 가지며, 새3세트는 청록 결정/적동 판금/보라 로브로 구분된다. 원래 캐릭터 geometry는 보존하고 흉갑·어깨·허리·태싯을 관절에 붙인다. 실제 UI에서 비늘 갑옷UID1을 장착해 HP2800→3018/방어40→45, armorAppearance.itemId=a_scale 및 몸에 부착된 메시를 확인했다.

갑옷 재질도 Player의 피격·사망·부활 효과 목록에 포함하며, 실제 Player 인스턴스로 flash/transparent true→false/전용 geometry 정리를 검사한다. 좁은 착용 창에서 발생한 카메라 잘림은 화면 비율에 따른 거리 계산으로 수정했다.

추가 실제 플레이: 비늘 갑옷을 입은 검성 아르카로 유리 정원5구역을 클리어했다. 16처치/34최대콤보, 골드676·원정XP100·영웅XP100·장비15개·강화석55가 한 번 정산됐다. 결과가 기존 게임의 모험 패널에 표시되고 상단 재화/하단 메뉴가 유지됐다. 영웅 메뉴로 직접 돌아가 실제 전리품 성기사 갑주로 교체해 의상 변경을 육안 확인했다. 검증 시계 app.testPause는 false로 복원했다.

새 영웅 화면은390×844에서 가로 넘침0, 착용 창322×210이며 캐릭터 전신과 의상·회전 버튼이 표시된다. 1280×800 가로 화면에서도 메뉴와 장비 목록이 동작한다. 이 확인은 IAB 뷰포트 테스트이며 실제 휴대폰 하드웨어 증명은 아니다.

## 완료 감사 후 사운드 연결 보완

Battle의 치명타가 기존 강타 샘플 플래그도 켜므로 가벼운 Flow 악센트가 실제로 선택되지 않는 경로를 찾았다. 콤보 마무리 여부를 별도로 전달해 치명타는 light, 마무리 강타는 heavy로 구분하며, 동시 타격 합성에서 마무리가 우선되도록 했다. 원정 시작·보스 등장·부활에는 Flow BGM을 계속 사용한다. 기존 캠페인은 기존 음악을 유지한다.

실제 IAB의 보통 속도 전투에서 유리 정원을 클리어하며 light 7회/heavy 4회의 AudioBufferSourceNode 시작을 관찰했다. 모든 AudioContext는 running 상태였고 보스 등장 후에도 Flow 전투 BGM을 유지했다. 별도 관찰 코드만 사용했으며 HP·스탯·승리·시간을 조작하지 않았다. 증거는 결과 파일 `flow-audio-runtime.json`에 보존했다.

## KayKit 전종 활용과 신규 실바 검증

무료 모험가 5종과 스켈레톤 4종의 사용 범위 및 출처는 `KAYKIT_ROSTER.md`에 기록했다. 신규 실바는 실제 Blender MCP로 제작한 의상·활 사격, 원본 얼굴과 23관절, 41동작을 갖춘 독립 영웅이다. 기존 4명과 기존 맵 파일을 보존했다.

최종 `bun run check`는 Bun1.4.2에서 232개/8528 assertions, 타입 검사, Vite 빌드가 모두 통과했다. 실바 모델 검사는 실제 GLB의 지오메트리·스킨·동작으로 수행하며 이미지 디코드만 Node 검사에서 제외한다. 중립 음성·초상화·모든 스킬 이미지의 실제 파일 존재도 검사한다.

IAB localhost5419에서 기존 저장을 불러와 실바 무료 지급→출전 선택→유리 정원 전투→보상 정산을 실제 UI로 진행했다. 실바 16처치/최대28콤보/3별 승리, 영웅 XP100으로 Lv2, 골드625/원정 XP100/유리 잎3을 확인했다. 관찰 표본에서 실제 화살과 마무리 화살, 집중 0/1/2/3 상태를 확인했다. 플레이 중 AUTO를 켜 마지막 탐색을 진행했으며 게임 시간·스탯을 주입하지 않았다. 178.76초 결과는 대기를 포함하므로 성능·클리어 속도 비교값이 아니다.

퀘스트 수령과 두 번의 정원 보상으로 유리 잎9개를 모아 유리 파수꾼의 갑옷을 제작했다. 실바에게 UI로 장착하여 HP1814→2282, 방어25→36, 전투력2811→3089와 실제 파란 갑옷 외형을 확인했다. 원래 얼굴·화살통·활은 유지됐다. 콘솔 error0, 실제 저장과 화면은 `ranger-runtime.json`, `ranger-armor-state.json`, `ranger-armor.png`로 보존했다.

`test/expedition-audio-routing.test.ts`의9개 회귀 검사는 실제 Battle.damageEnemy→AudioSys.hit 경로의 일반/치명/마무리 조합, 동시30타 우선순위, 음소거 취소, 캠페인·던전·결투의 보스/부활 음악 선택을 확인한다. 보완 후 전체221개 테스트/8092 assertions, 타입 검사·빌드를 확인한다.
