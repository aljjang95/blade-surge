# 초보자 마을 Tripo 소품 정규화 (starter-village-v1)

Tripo(HD H3.1, 리토폴 Triangle)가 만든 소품 GLB 8종을 게임용으로 정규화한 기록이다. 원본은 저장소에 커밋하지 않는다.
원본 위치는 `origin/art/starter-village-concepts` 브랜치의 `tripo/<이름>/model.glb`(+ `front.png`, `top.png`, `tripo/RESULT.md`)이고, 이 문서는 원본을 아래 sha256으로만 참조한다.

## 실행 환경
- Blender 5.2.1 LTS(`hash 9e2066aef7ef`, 2026-08-25 빌드) Linux x64 tarball을 `~/.local/blender/blender-5.2.1-linux-x64/` 에 풀어 썼다(sudo 없음). `build-citadel-assets.py` 와 같은 5.2.1.
- 재현: `tools/build-starter-village-props.py` 머리 주석의 순서(원본을 `work/tripo-src/` 로 풀기 → `blender --background --python tools/build-starter-village-props.py [-- 이름...]`). 8종 전체 약 1분 50초(4코어, 미리보기 렌더 포함).
- 산출: `public/models/starter-village-v1/<이름>.glb`(이름은 `sv_` 뺌), 미리보기 `work/art/starter-village-v1/<이름>-{front,top}.png`(커밋 안 함, 정면 사진에는 영웅 키 1.8m 빨간 기준 막대), 수치 원본 `work/art/starter-village-v1/report.json`.

## 정규화 기준
- 피벗: 바닥 중앙(최저 y=0, x/z 바운딩 중심 0), 단위 m, 노드 1개·메시 1개·재질 1개.
- 앞방향 +Z. 절차 코드의 `local(x0, z0, yaw)` 는 three.js 표준 `rotation.y = yaw`(로컬 +z 가 앞, 오두막 문·대장간 화로·게시판 글이 모두 +z)라서 GLB 앞면을 +Z 로 두면 `node.rotation.y = yaw` 만 주면 된다. 판정 근거: Blender 5.2 가져오기에서 glTF +Z 는 -Y 이고, -Y 쪽 카메라 렌더가 Tripo `front.png`(오두막 박공·굴뚝 오른쪽, 대장간 화덕, 포탈 계단·깃발, 상점 진열대)와 8종 모두 같은 면이었다. GLB 의 POSITION 접근자로도 최저 y=0, x/z 중심 0 을 확인했다.
- 스케일: 균등 스케일 하나. 폭(x)·깊이(z)·높이(y) 한도 중 가장 먼저 닿는 축에 맞춘다. 허수아비는 충돌이 기둥 반경 .38 뿐이라 높이(영웅 키급) 우선.
- 삼각형 예산: 건물(오두막·대장간·포탈·분수·상점) ≤6,000, 소품(게시판·허수아비·영웅상) ≤3,000. 넘는 것만 Decimate(collapse)했다(오두막·대장간·게시판·영웅상). 실루엣 확인은 미리보기 정면·위 렌더로 했다.
- 텍스처: 베이스컬러 건물 1024px, 소품 512px; 러프니스/메탈릭(rm) 512px 유지; 노멀 맵 제거(리토폴 뒤라 효과 작고 용량이 큼). WebP 로 내보내 `EXT_texture_webp`(required) — 저장소의 `models/heroes-next/*.glb` 와 같은 규칙이고 three GLTFLoader 가 지원한다. `tools/optimize/glb.mjs` 는 이 GLB들을 "deflate 후 이득 없음"으로 건너뛰며 오류는 없다.
- 메탈릭 값은 Tripo 가 구운 값 그대로다(평균 .08~.18, 포탈·상점 금속부는 최대 .9 이상). 원본 그대로 유지.

## sv_stall 결함 처리
RESULT.md 의 "차양 윗면 검은 구멍 2~3개"를 확인한 결과 메시 구멍이었다(원본 정점이 UV 이음선마다 갈라져 있어 정점 병합 후 경계 변 34개, 구멍 덩어리 8개).
- 차양 윗면 구멍(약 0.7 × 0.3 m, 경계 11변): 무게중심 부채꼴 삼각형 11면으로 덮고, 구멍 가장자리의 천 색(흰·파랑) UV 를 가장 가까운 후보로 줘 줄무늬 색을 이었다. 미리보기 위·정면에서 검은 구멍이 사라졌다. 다만 덮은 자리는 줄무늬가 단순화된 평면이고 일부 면이 연한 회색 음영으로 보인다(굽은 천 모양은 복원 못 함).
- UV 안쪽 검은 얼룩(천 둘레 5곳, 약 11,800 px)은 둘레 색으로 메웠다.
- 상점 앞 장식 깃발의 구멍(경계 8변)은 삼각형 채우기를 시도했지만 오목한 모양이라 일부가 검게 남았다(미해결).

## 비례·이상한 점
- 오두막: 높이 4.2 m 로 1층형 절차 모델(약 5.1 m)보다 낮고, 영웅 기준 막대(1.8 m)가 1층 창 아래쪽까지 와서 1층이 인형집 비율이다. 앞면(+Z)에는 문이 보이지 않는다(창만 있음). 문 높이는 영웅과 비교할 수 없으므로 문을 쓰려면 측면 확인 또는 문 장식을 따로 붙여야 한다. 깊이 한도(4.2)에 먼저 닿아 폭이 3.54 m 로 줄었다(절차 모델은 5.4 m).
- 대장간: 절차 모델은 6.2 m 폭의 열린 작업장인데 Tripo 는 4.1 × 4.0 m 의 닫힌 건물(앞면 화덕 개구부)이다. 충돌(기둥 4개 + 뒷벽 5.8 m)과 맞지 않아 다음 레인에서 충돌을 새로 정해야 한다.
- 분수: 높이 1.74 m(절차 2.3 m). 영웅(1.8 m)보다 낮고 물줄기 원뿔(절차 y=1.8)은 가운데 기둥보다 높다. 장면의 물줄기 위치를 낮춰야 한다.
- 게시판: 2.21 m(절차 2.8 m). 영웅 머리가 하단 프레임 위로 오는 정도라 적당하다.
- 상점: 폭 2.6 m 는 충돌 사각형 길이 2.6 m 와 맞으나 깊이가 2.09 m 라 충돌 깊이 1.0 m 보다 크다(차양 포함). 앞 소품 충돌과 어떻게 맞출지 다음 레인이 정한다.
- 영웅상: 3.54 m, 받침 지름 1.9 m. 허수아비 1.86 m 는 영웅 키와 같다.

## 미해결
- 상점 앞 장식 깃발 구멍 일부, 차양 덮개의 단순화된 면(정식 수정은 Tripo 리토폴 값을 올려 재생성이 안전).
- 영웅 머리 높이 실측(스키닝 메시), 오두막 문, 실제 장면에서의 앞방향·그림자 확인은 장면 코드(src/) 연결 뒤에 한다. 이 레인은 `src/` 를 건드리지 않았다.
- 노멀 맵을 뺐으므로 장면 조명에서 표면 요철이 약하면 베이스컬러 음영에 의존한다.
