# 앱 화면·네브·파티 연결 QA — 2026-09-13

Chrome 주소창이 게임 공간을 차지하는 문제에 로비와 일시 정지 메뉴의 **앱 화면** 진입을 추가했다. 실제 사용자 클릭으로 Fullscreen API를 호출하며, 지원하지 않거나 거절한 브라우저는 홈 화면 설치 방법을 안내한다. 설치 완료와 현재 앱 화면 실행을 구분한다. Manifest는 fullscreen → standalone을 선택하며 기존 앱 식별자와 저장 데이터를 유지한다.

네브는 로비 메뉴 흐름 안에 배치했다. 짧은 세로 화면에서는 11개 메뉴를 3열·4행에 배치하고 44px 이상의 터치 영역을 유지한다. 로비 대화창이 전투로 따라와 자동으로 멈추는 동작을 제거했다. 첫 대화 패널 로딩 후 임시 버튼이 중복으로 남는 회귀도 실제 브라우저 테스트에서 찾아 수정했다.

파티는 렌더 프레임과 독립적으로 4초마다 연결 확인 신호를 보낸다. 서버 응답(16초)과 방장 전투 정보(60초)를 별도로 확인한다. 동료에게 방장 일시 정지·응답 대기를 안내하고, 화면 복귀 후 새 전투 정보가 도착할 때까지 입력을 비운다. 기존 준비·방장 권한·빈도 제한·생성 후 45분 만료·개인 보상 격리는 유지한다.

## 실제 검증

- 최종 소스 타입 검사 및 569개 테스트 / 58,461 assertions 통과. 빌드 성공.
- Chromium·Firefox·WebKit 각각 320×568, 390×844, 667×375에서 메뉴 11개 터치 중심·44px 터치 영역·화면 범위·네브/출격 겹침 없음 확인. 설치 안내 열기/닫기/초점 복귀, 네브 실제 첫 열기/닫기/단일 버튼/초점 복귀 통과. 브라우저 콘솔·페이지 오류 0.
- Chromium·Firefox의 실제 클릭에서 전체 화면 진입/종료 통과. 이 Windows WebKit 런타임은 Fullscreen API가 없어 설치 안내 경로를 확인했다.
- 실제 localhost workerd + Durable Object + 두 격리 브라우저 파티: 181.395초 유휴 유지, 실제 host44/guest41 ping·pong 교환. 이후 방장 일시 정지/재개, 동료 시계와 안내, 세 화면의 파티 표시/전투 조작 영역 겹침 없음 확인.
- 실제 서버 연결을 유지하면서 게스트 수신 프레임만 차단하는 명시적 네트워크 fault test: snapshot만 차단해도 pong이 계속 오는 동안 3.057초에 방장 대기, 61.926초에 원정 종료. 전체 수신 차단 시 16.428초에 서버 응답 종료. 수치는 첫 통합 빌드의 측정값이며 최종 빌드 재검증 기록은 별도 JSON에 보존한다.
- 독립 리뷰에서 화면 복귀 직후 입력 누출과 짧은 세로 화면의 4번째 메뉴 행 위험을 발견했다. 새 snapshot까지 입력 차단 및 메뉴 높이 조정으로 수정하고 회귀 테스트했다.

## 증거와 범위

`app-screen-20260913.json`은 최종 UI 3엔진 기록이며 `app-screen-assets-20260913.json`에 테스트된 정적 파일 해시를 묶었다. 파티 최초 유휴/장애 측정은 `party-presence-initial-20260913.json`, 최종 빌드 장애/정지·재개 재검증은 `party-presence-release-20260913.json`이다. 테스트 중 게임 상태·스탯·시계·배치를 직접 대입하지 않았다. 네트워크 fault 주입은 물리적 통신 장애 재현과 구분한다.

기존 c48 배포의 실제 IAB 두 클라이언트에서 191.642초 유휴 종료는 재현되지 않았고, 방장 pause에 대한 게스트 안내 누락만 확인했다. 이전 3분 내 종료의 근본 원인은 아직 확인되지 않았다. 새 heartbeat가 그 원인을 해결했다고 주장하지 않는다.

최종 단계에서 실행 환경이 managed/read-only로 변경됐으며, 필요한 프로젝트 쓰기·개발 통신 권한은 승인됐다. IAB와 이미지 보기 도구는 Windows sandbox helper의 SetNamedSecurityInfoW 오류(5)로 실행되지 않아 최종 수동 IAB 재검증은 하지 못했다. 보호 설정을 변경하거나 외부 계정 브라우저로 우회하지 않았다. 최종 UI 증거는 승인된 로컬 프로젝트 브라우저 테스트의 실제 조작·스크린샷·DOM 측정이다.

물리적 iPhone/Android 설치, 실제 Chrome/Safari/Samsung 앱의 주소창·OS 공유 메뉴, 기기 발열·장시간 성능은 미확인이다. 엔진 에뮬레이션을 모든 모바일 브라우저 인증으로 취급하지 않는다. 기존 콘텐츠/스토어/광고·결제 출시 목표는 이 패치의 완료와 별도다.
