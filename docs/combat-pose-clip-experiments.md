## 탐색 준비

- `bun install --frozen-lockfile` 완료. 개발 서버는 전용 5301 포트.
- 변경 전 117개 감사 실행 중. 측정 중 src 수정 금지.
- 이전 `optimize.mjs`의 요약 생성이 `frames.sort()`로 원본 재생 순서를 바꾼다. 이후 smooth3의 인접 프레임 속도 추정이 재생 순서가 아닌 목록을 사용한다. 이번 복제 탐색기는 `[...frames].sort()`로 요약만 정렬하며 시간 순서를 보존한다. 측정 도구는 그대로다.
- 초기 실험: 기존 24개 시간 키와 40도 크기 제한에서 시작하고, 실제 시간 순서의 구간별 변화율로 다시 탐색한다. 속도 제한 완화는 전후 캡처·연속성 수치와 함께만 채택한다.

## 검증 및 인계

## 변경 전 재현과 1차 실험

- 동일 도구·기준으로 117개 재현: 정상 8, 판정불가 80, 결함 19, 오탐 10, 페이지 오류 0. 직업별 결함: 기사 5, 야만전사 2, 마법사 0, 도적 0, 궁수 12.
- 30도/프레임 및 제한 사실상 제거(시험 전용 모듈 교체)로도 해결되지 않았다. 따라서 전역 속도 제한 제거는 채택하지 않는다. 부분 동작 목록만 실행한 실험이므로 전체 117개 개선 수치로 사용하지 않는다. `rate-verified.log`는 모듈 교체가 실제 적용됐음을 확인한 별도 1건 시험이다.
- 40도/24키 재탐색: 기사 가로 베기 95개 표본 중 6개, 회전 41개 중 3개 실패. 실제 프레임 순서를 보존해도 기존 크기 제한만으로 이 탐색은 통과하지 못했다. 이는 해결 불가의 증명이 아니다.
- 60도/24키 탐색: 기사 가로 베기 1/95·회전 2/41, 야만전사 회전 3/142 실패. 48키로 접촉 전후 구간을 다시 탐색 중이다.
- 궁수 일반 사격은 현행 표에 항목이 없다. 과거 스크립트 기록에는 40도 범위에서 95개 실패가 남았다. 이번 60도 탐색에서 474개 표본이 통과했으나 활을 든 왼팔 회전까지 바뀌므로 그대로 채택하지 않고, 왼팔 네 관절은 원본에 고정한 채 오른팔만 재탐색한다.
- 위 표본 통과는 정식 117개 감사의 통과가 아니다. 실행 시 속도 제한·교차 페이드가 적용된 전체 도구 결과를 별도로 기록한다.

## A3 도달성·육안 확인 진행

- `src/main.js:interactHub`는 `hubUI.interact`를 호출하고 애니메이션을 재생하지 않는다. `src/game/hub-movement.js:_setMoving`은 `Running_A`/`Idle`만 선택한다. `Interact`는 로더의 필수 별칭이지만 현재 마을 플레이 경로에서는 호출되지 않는다. 감사기의 `hub-clip`만 `stopAllAction` 뒤 즉시 재생한다. 117개 집계에서 이 두 항목을 제외하지 않는다.
- 판정불가 80건의 캡처는 정면·측면·후면으로 육안 확인했다(중복 클립은 대표 캡처 공유). 도적 `night_parade`는 재시전 시 표본 길이가 달라 기본 도구가 캡처를 남기지 못해, 같은 측정 함수를 순차 재생하면서 최악 프레임을 즉시 캡처하는 보충 스크립트로 확인했다.
- 방패의 팔 껍질 과대, 팔과 어깨 이음매, 다리 사이 빈 공간의 볼록 껍질은 피부 관통과 구분한다. 마법사의 지팡이와 모자챙·머리카락 겹침은 별도 시각 결함으로 남기며 A1의 두개골·몸통 판정에 합격했다고 숨기지 않는다.
- 검토 표와 캡처 참조를 최종 결과에 함께 기록한다.

## 60Hz 이후 보간 구간 추가 검사

- `92e95989`에서 원본 117개 감사는 결함 0이었다. 추가 240Hz 검사에서 기사 회전 베기와 야만전사 회전의 표본 사이 관통이 발견되어 최종 완료 판정을 보류했다.
- 원본 60Hz Idle을 먼저 만든 뒤 `app.step(dt/4)`로 시간만 세분하고 원본 메시 측정 함수를 매 표본에 호출했다. 이 추가 탐색은 정식 117개·3cm 기준을 대체하거나 완화하지 않는다.
- 96키·60도 재탐색에도 기사 7개, 야만전사 3개 표본이 남았다. 팔을 안전한 한 자세에 고정한 다섯 후보는 칼·도끼 5~19cm 겹침으로 실패했다. 전 구간 손목 회전도 실패했다.
- 접촉 구간에만 손목 펄스를 넣고 RightHand 한 관절의 허용 보정각을 120도로 제한한 재탐색: 기사는 Z+90도 초기 후보 뒤 0/167, 야만전사는 Y-90도 초기 후보 뒤 0/586(원본 자세 위 계산). 다른 관절은 60도 이하다. 이 계산만으로 런타임 통과를 주장하지 않는다.
- Euler 축별 보간은 동등한 회전의 표현 차이를 길게 돌아 손목이 뒤집힐 수 있다. 두 키를 quaternion으로 변환한 뒤 최단 경로 slerp하는 미리보기를 추가했다. 야만전사 스킬의 실제 240Hz는 통과했으나 일반 공격 첫 프레임이 3.3cm로 남아 굽기 표본 주파수와 전환 경계를 추가 확인 중이다.
- 아직 소스에는 손목 120도 및 quaternion 후보를 채택하지 않았다. 기존 14.5도/프레임 연속성 정책을 바꾸는 모든 채택은 수치와 비교 캡처를 함께 남긴다. 해법 탐색의 실패는 해결 불가 증명이 아니다.
