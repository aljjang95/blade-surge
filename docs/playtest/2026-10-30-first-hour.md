# 첫 플레이 표본 (3개월 R7 QA, 2026-10-30)

대상: 운영 `https://blade.tllhouse.com` 신규 게스트 1계정(프로필 a). 봇 `tools/qa/playtest-first-hour.mjs`.
스크린샷은 커밋하지 않는다(`work/qa/playtest-a/`, 컨테이너 임시). 필요하면 재실행으로 다시 만든다.

## 증거 수준 (이 표본이 말할 수 있는 것)

| 구분 | 내용 |
|---|---|
| 실제 입력 | 부팅·게스트 시작·가로 전환 안내·출격·입장·튜토리얼 직접 조작(CDP 터치 조이스틱 4방향 + 공격)·결과 버튼·출석 보상 창은 실제 DOM 탭·터치 이벤트 |
| 가속 | 전투 중 "기다리는 구간"만 `app.step(0.05)`로 빨리 감음(전투 판정·AI는 게임 코드 그대로). 시각표의 분 = 전투 게임 시간 + 메뉴 벽시계 |
| 환경 | 컨테이너 헤드리스 Chromium, 소프트웨어 GL(SwiftShader). 실기기·GPU·발열·실제 손가락 아님. Threads 인앱 UA 문자열 + 390x700 |
| 미수행 | 프로필 b(844x390 가로 1시간), 성장 개입(강화·스킬·소환·장비) 플레이. 봇은 AUTO 전투만 한다 |

따라서 D2(첫 30분 실제 입력 표본)는 **부분 충족**(온보딩~1-3 벽까지), D3(첫 1시간)은 **미충족**이다.

첫 보스·첫 소환·첫 강화·현상금 의뢰판은 봇이 성장 행동을 하지 않아 이 표본에서 시각을 못 쟀다(unknown).

## 결함·관찰 (심각도순)

1. **[수정함] 세로 화면에서 튜토리얼 카드가 상단 HUD를 덮음** — 390x700 펼침: 카드가 미니맵을, 접힘 버튼이 MP 바를 덮고, 접힌 버튼은 카메라 자동 버튼과 겹침. 수정은 `src/ui/tutorial.css`, 측정은 `tools/qa/tutorial-hud-overlap.mjs`(390x700·360x640·844x390·667x375, 펼침·접힘 모두 겹침 0). 수정 전 14건·2건.
2. **[관찰·이탈 위험] AUTO만으로는 Lv.4 기사가 1-3에서 막힘** — 쓰러짐 2회(13:49, 18:14). 이용자는 부활(보석 50) 또는 정비하기를 골라야 하고, 결과 화면의 "스킬 강화 ›" 등 성장 안내가 그 해법이다. 성장 안내를 따르는 플레이로 1-3을 넘는지는 이 표본에서 미확인 → 다음 덩어리(봇 성장 행동 추가).
3. **[관찰] 세로 화면 가로 전환 안내가 로비 도착 직후 뜨고, 안 닫으면 모든 탭을 가로막음** — "세로로 계속하기"를 눌러야 풀린다. 결과 창이 열려 있는 동안에는 숨었다가 닫히면 다시 나타난다(`body.force-landscape`). 설계 의도로 보이나 인앱 브라우저 이용자의 첫 장면이다. 봇은 탭 전에 닫도록 처리.
4. **[관찰] 첫 승리 뒤 로비에 출석 보상 창이 자동으로 뜸** — 정상 기능. 1-1 직후라 첫 30분 안에 닫기 한 번이 더 필요하다.
5. **[관찰] 결과 화면 로비 버튼 탭이 가끔 Playwright 안정성 대기(5초) 초과** — 전설 카드 반짝임 애니메이션 중. 이후 재시도로 진행. 이용자 입력 실패로 확정하지 못함.
