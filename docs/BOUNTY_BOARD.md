# 현상금 의뢰판 (3개월ㄱㄱ 첫 덩어리, 2026-10-30)

`[gogo-chunk:3month-highend#1]`. 플레이타임 장부 기준선에서 마라톤(하루 8시간) 1일차 312분·2일차 369분·3일차 246분이 "할 일 없음"(에너지 고갈)이었다. 첫날(P1)이 7.5h 중 2.4h(verified)만 찬다. 이 덩어리는 에너지가 바닥난 뒤에도 의미 있는 고유 목표를 주는 활동을 넣는다.

## 2. 규칙 (`src/data/bounties.js`, `src/game/bounty-board.js`)

- 의뢰판 개방: 1-10 클리어(1장 마을 개방과 같은 순간).
- 의뢰 id `단계:장-관문:종류` (`story:1-4:trial`). 단계 story는 별 1 이상, adept·nightmare·hell은 `endgame.peak[key] ≥ rank`.
- 종류: hunt(3분, 경험치 10, 증표 1, 골드 몫 0.4) · trial(4분, 14, 2, 0.5) · wanted(X-10만, 6분, 30, 5, 1.0). 단계 배율 골드 1/1.4/1.9/2.6, 경험치 1/1.2/1.4/1.7, 어려운 단계 +1분.
- 조건 의뢰 조건은 관문·단계 해시로 고정: 신속(`time` 240초 이하)·버티기(`revives` 0, 쓰러지지 않음)·연격(`maxCombo` 25 이상)·완벽(`stars` 3). 전투 결과 객체가 실제로 노출하는 필드만 쓴다(피격 횟수·물약 사용은 결과에 없음). 결과에 그 사실이 숫자로 없으면 실패.
- 저장 `done['단계:장-관문'] = 비트마스크`(1 hunt, 2 trial, 4 wanted). 전부 끝내도 약 280키·수 KB(D10 저장 상한 안).

## 3. 시뮬레이터 (`tools/sim-90d.mjs`)

- 우선순위: 새 관문 → 무한의 성 → 새 난이도 → 성 추가 → 에너지 반복 → **현상금 의뢰(에너지 0)** → 고통 단계.
- 같은 규칙 함수(`availableBounties`·`completeBounty`·`buyBountyItem`)를 쓰고 시간은 `def.minutes`. 판정은 시뮬레이터에서 항상 통과(조건 재시도 시간은 분에 포함).
- 일별 로그 `bountyMin`·`bountyDone`·`hunterRank`.

## 4. 남은 게이트

- 첫 1시간·인앱 390x700 실제 입력 표본(dod D2·D3).
- 의뢰 분(3/4/6분)은 시간 모델이다(AUTO 1-1~1-3 실측 144~211초 기반). 텔레메트리로 바꿀 것.
